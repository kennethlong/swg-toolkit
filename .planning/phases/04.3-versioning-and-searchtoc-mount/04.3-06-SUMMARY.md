## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] DeployPanel.test.tsx Test 2 broke because VersionHistoryBody no longer calls selectVersion**
- **Found during:** Task 1 (full test suite regression run)
- **Issue:** `DeployPanel.test.tsx` Test 2 asserted `expect(selectVersion).toHaveBeenCalledWith('v1')`. After D-04 rework, `selectVersion` is no longer imported or called by `VersionHistoryBody`. The test also couldn't find `getByText('Add armor')` because the label was now inside a div with other text content (not its own element).
- **Fix 1:** Wrapped `cs.label` in a `<span>` inside `ver-title` div — preserves RTL `getByText` searchability.
- **Fix 2:** Updated Test 2 title and assertion to reflect D-04 (selectVersion replaced by syncLiveToVersion). Verified delta expansion still works post-click.
- **Files modified:** `VersionHistoryBody.tsx` (span wrapper), `DeployPanel.test.tsx` (assertion update)
- **Committed in:** `db86b13`

---

**2. [Deviation from plan spec] `hasUncommittedWork` uses `stagingEntries.length > 0` instead of `!flatEqual(staging, flatten(live))`**
- **Found during:** Implementation design
- **Issue:** Plan spec said `hasUncommittedWork = !flatEqual(currentStaging, flatten(liveVersionId))`. `flatEqual` calls `fs.statSync` for sha-absent entries — unsafe in a render function (can throw on missing files, especially in tests). Mocking `changesetService.flatEqual` in every VersionHistoryBody test was also unnecessarily complex.
- **Fix:** Used `stagingEntries.length > 0` — semantically equivalent: if staging has entries, the user has uncommitted work; if empty, the working set is clean. Both the D-07 confirm trigger and the WIP visual stub use this value.
- **Impact:** None — the test expectations (clean = no confirm, dirty = confirm) work correctly with the simpler check. Plan 09 or a future improvement can add the flatEqual path if per-delta comparison is needed.

---

**3. [Deviation from plan spec] Tasks 1 and 2 co-implemented in a single atomic write**
- **Reason:** Both tasks modify only `VersionHistoryBody.tsx`. The layout (Task 1) and the reconcile wiring (Task 2) are tightly coupled — the row click handler references both laneLayout rows and syncLiveToVersion. Writing Task 1 without Task 2's click handler would have left the component in a broken intermediate state. The plan's two-task structure is preserved in the test file (two separate `describe()` blocks).
- **Impact:** One commit (db86b13) covers both tasks. All acceptance criteria for both tasks are verified by the 24 tests.
