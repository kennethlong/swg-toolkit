<decisions>
## Implementation Decisions

### Phase shape & sequencing
- **D-01:** **One phase, multi-plan.** Pillar A, Pillar B, and the 007/008 polish stay in 04.3 as
  separate plans/waves — not split into 04.4.
- **D-02:** **Parallel waves.** Pillar A (renderer/deploy) and Pillar B (native-core) touch different
  layers → run as concurrent waves, converge at the UAT.
- **D-03:** **One combined in-client UAT** at the end (autonomous:false) on BOTH a searchTree client
  (SWGEmu/Infinity, absolute-path) and the searchTOC dev client (swg-client-v2, loose-override), with
  the full v6000 base mounted + branch-tree rendering. It closes 04.1-11 + 04.2-06 + 04.3 in one pass.

### Version-navigation model (Pillar A core — the load-bearing UX decision)
- **D-04:** **Click an existing version = instant, SILENT reconcile of the live client to it**
  (`syncLiveToVersion`), using *that version's own stored deploy-model* (absolute/loose). No dialog,
  no "now press Deploy." The version tree IS the deploy control. This replaces today's "select =
  preview only, Deploy button = apply" two-step (which the maintainer explicitly rejected).
- **D-05:** **The Deploy button/dialog is ONLY for publishing a NEW version forward** (staged working
  changes → Save → new node → Deploy to pick its model the *first* time). It is NOT a step for
  navigating among existing versions. After first deploy, a version remembers its model and D-04 drives it.
- **D-06:** **Session undo stack** backs every reconcile (silent + undoable; cf. the
  `delete-project-with-restore` undo-stack idea — park in a session-scoped snapshot stack).
- **D-07:** **Confirm appears ONLY when uncommitted working changes would be discarded** by navigating
  away ("Discard unsaved changes and switch to vN?"). Not a routine second-step — only when there's
  something to lose. Normal navigation is silent.
- **D-08:** **Selected ≡ live, always.** No preview-limbo / no "active ≠ deployed" divergence. To
  *inspect* an old version's files without reconciling, use the row's ▸-expand (lists changed files).
- **D-09:** **Per-row Deploy/Revert hover actions DROPPED** (clicking already reconciles, so they're
  redundant). **"Branch from here" KEPT** (the one action a click can't express). This is a deliberate,
  maintainer-approved divergence from sketch 002-A's per-row Deploy/Revert buttons.
- **D-10:** Deploy-model picker (absolute/loose/Advanced) shown ONLY for a new forward deploy (D-05);
  hidden when navigating/reverting to an existing version (per the Pillar-A todo).

### Branch-tree visualization
- **D-11:** **Proper multi-lane tree layout** — real lane assignment, any number of branches at any
  depth, connector lines + branch-from curves. Bounded: the model is a single-parent rooted **tree**
  (no merges), so simpler than a general git-DAG.
- **D-12:** **Render with a graph library** — maintainer's choice over hand-rolled SVG. **RESEARCH
  GATE:** the chosen lib MUST faithfully render sketch 002-A (90px lane gutter *beside* independently
  laid-out row content, CSS-var accent theming, custom node templates, the dashed uncommitted-changes
  stub). Many git-graph libs fuse the node+row into one unit and can't do this layout — **if no lib
  clears the gate, fall back to hand-rolled SVG.** (Sketches are the contract — do not let a lib's
  default rendering re-introduce sketch drift; that drift is the exact reason this phase exists.)
- **D-13:** **Markers collapse to ONE "live" node** (accent-filled, where the client is now) + root
  marker + branch-point markers + branch-from connectors + dashed uncommitted-changes stub above the
  live node. The sketch's separate "active (cyan)" vs "deployed (blue)" distinction is dropped because
  D-08 makes them the same node; the stale/active≠deployed concept goes away.

### Pillar B — searchTOC / v6000 mount
- **D-14:** **Full depth this phase: entries + extraction.** Source ALL entries from the master `.toc`
  (v6000 empty-internal-TOC containers contribute), AND extract payloads. v6000 `isEnumerateOnly`
  becomes a **per-payload runtime check** (attempt inflate; classify as Restoration-encrypted only on
  real failure). Avoid double-counting paths that are both self-indexed and master-indexed.
- **D-15:** **Lazy searchPath lookups** (the more client-faithful fix, maintainer's choice over the
  simpler "overlay top dir + skip archives"). Stop upfront enumeration of searchPath dirs; resolve loose
  overrides on-demand at lookup time like the real client. Consequence to honor: loose files are NOT
  listed as flat VFS browser rows; the override still **wins at resolve time**, and the viewer reads the
  loose winner from disk via the shared `readVfsEntryBytes`. This IS the over-enumeration fix.
- **D-16:** **Verification gate = de-anchoring crew + byte-exact test (skipIf-absent).** Run the crew
  (Codex/Cursor/Sonnet/Opus) against real swg-client-v2 source + real `.toc`/`.tre` bytes + the
  maintainer's working `swg-blender-plugin/swg_pipeline/tre_reader.py` BEFORE merging the mount changes;
  add a native byte-exact test on a real v6000 asset (skipIf assets absent, per prior phases).

## Existing Code Insights

### Reusable Assets (reuse, do NOT rebuild — per the Pillar A todo)
- **Per-version file folders** `studios/<project>/changesets/<versionId>/files/` already store each
  version's bytes; `changesetService.flatten(versionId)` reconstructs the full set by walking parentId.
- **Per-version `deployRecord`** (CfgDeployRecord | LooseDeployRecord) already on each `SwgChangeset` —
  the deploy-type tag exists; the rework makes it drive revert (D-04).
- **Revert/apply primitives** already exist: `looseOverrideDeploy.deployLoose/resetLoose` (B3
  snapshot+restore), `cfgActivator.restoreCfg/activatePatch`, absolute-path writer.
- **Pointers** `manifest.activeVersionId` + `deployedVersionId` (the latter becomes the single "live" pointer per D-08).
- **`readVfsEntryBytes(entry, mountHandle)`** (a3b825f) — loose→disk, archived→mount; reuse for D-15 viewer reads.
- **`tocReader.readTocIndex`** (04.2-03) already parses the master `.toc` but the mount never used it for
  entry-sourcing — D-14 wires it in.

### Established Patterns
- TRE entries cross the bridge as ONE columnar ArrayBuffer (getMountEntriesColumnar, off-thread); VfsTree
  virtualized. Lazy searchPath (D-15) must not regress mount perf.
- Native addon statically links zlib (Electron renderer crash otherwise) — relevant to v6000 inflate (D-14).
- `syncLiveToVersion` = diff-and-apply between `flatten(target)` and the live set; one op covers
  forward-apply AND backward-revert; Baseline = flatten(BASELINE) = empty = full restore-to-stock.

### Integration Points
- New deploy-navigation service couples version selection → reconcile (D-04), wired to VersionHistoryBody
  row click + the session undo stack (D-06).
- Pillar B master-index mount replaces per-`.tre` internal-TOC sourcing for searchTOC clients only;
  searchTree clients (SWGEmu/Infinity) unaffected (regression guard, todo AC#6).

<specifics>
## Specific Ideas

- The maintainer's mental model: "navigating the tree IS deploying" — the version tree is the deploy
  control, not a preview pane. Frictionless by default; undo + a single unsaved-changes confirm are the
  only safety interrupts. (D-04/D-06/D-07.)
- Branch off a non-tip version must DRAW as a branch (the data model already sets parentId correctly; the
  flat-list renderer just never showed it). (D-11.)
- v6000 is plain zlib for SWG-Source (FALSIFIED the old "exclusively Restoration-encrypted" memory) — the
  working extractor + the SWG-Source client mounting these files is ground truth. (D-14.)
