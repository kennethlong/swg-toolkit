# Phase 04.3 Plan 03: Wave-0 Pillar-B Fixtures + Typing Stubs Summary

Swg-source v6000 plain-zlib byte-exact fixture extracted and committed; native `extractMountAt` + `mountTreMountWithToc` typing stubs frozen in `index.d.ts`; three RED test scaffolds exist for plans 10 and 11.

## What Was Built

### Task 1 — swg-source v6000 byte-exact fixture + MOUNT-03 oracle test

**Extraction script** (`extract-v6000-fixture.mjs`): Reads `D:/Code/SWGSource Client v3.0/sku3_client.toc` using the same 24-byte entry layout as `tocReader.ts`, filters for the smallest zlib entry in a `patch_sku3_*` container (non-tombstone, compressor=2, length≤64KiB), bounds-checks offset+compressedLength against the container file size (T-04.3-03-03), and emits three fixture files.

**Fixture chosen**: `appearance/lod/thm_must_droid_factory_exterior.lod`
- Container: `patch_sku3_24_client_00.tre` (EERT6000, `numberOfFiles=0`, plain-zlib payload)
- Offset: 26174 · compressedLength: 564 · length: 1092 · compressor: 2 (zlib) · crc: 0x058f215e

**Three committed fixtures** in `packages/harness/fixtures-real/toc/`:
- `*.v6000.zlib.bin` (564 bytes) — raw compressed bytes as stored in the .tre
- `*.v6000.expected.bin` (1092 bytes) — zlib-inflated ground-truth oracle
- `*.v6000.descriptor.json` — full entry metadata (container, offset, lengths, compressor, crc)

**Byte-exact test** (`tre-v6000-swgsource-byteexact.test.ts`): Uses `test.skipIf(!fixturesPresent)`. On dev machine (fixtures committed): inflates `.v6000.zlib.bin` with Node.js `inflateSync`, asserts byte-equal to `.v6000.expected.bin` → PASSES. On CI without real client: SKIPS cleanly.

De-anchoring note documented in README: v6000 is DUAL-format (SWG-Source = plain-zlib, Restoration = encrypted). The fixture targets the plain-zlib variant only.

The tombstone test passes (both unimplemented-method and correct-tombstone-filter return `undefined`).
