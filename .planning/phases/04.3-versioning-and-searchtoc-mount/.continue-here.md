## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| False-positive persistence assertion | E2E `SC-5 REAL RESTART` "passed" on layout because `WorkspaceShell.onDidLayoutChange` **rewrites the layout key on every boot** — so `restoredLayout != null` proves nothing. The theme key (only written on user action) is the honest probe, and it's `null` after restart. | advisory | When testing cross-restart persistence, probe a key that is NOT rewritten on boot. F-9 quarantined (`test.fixme`) + manual check A-P added. |
| Undefined-var shell redirect no-op | `npm run test:e2e > "$TMP_E2E"` with `$TMP_E2E` unset silently made the redirect fail (exit 1, suite never ran). | advisory | Don't redirect background output to a var; the harness captures stdout itself — run the bare command. |
