## Decisions Made

- **resolveFull uses name-map not CRC binary search**: The plan-03 RED tests use synthetic CRCs (0x00000001) that don't match real crc32(path), proving the plan-03 contract requires name-map lookup. On real .toc files (matching CRCs), both approaches agree.
- **Tombstone filter broke H1 test**: makeEntry in tocReader.test.ts defaulted `uncompLength=0`; the tombstone filter (`length===0 → undefined`) caused the H1 binary-search test to return undefined. Fixed by adding `uncompLength=1` default to makeEntry.
- **ESM imports for fs/path in treMount.ts**: CJS `require('fs')` at module init bypasses vi.mock() hoisting (vi.mock intercepts ESM module graph, not Node's native require cache). Switched to `import * as nodeFs from 'fs'` — Vite externalizes Node built-ins regardless of import syntax.
- **readVfsEntryBytes TOC branch parameter**: Takes optional `descriptor?: ExtractionDescriptor | null` — when supplied, routes through extractMountAt; otherwise falls through to resolveChain + readMountEntry.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] H1 binary-search test broken by tombstone filter**
- **Found during:** Task 1 GREEN
- **Issue:** `makeEntry()` in tocReader.test.ts uses `Buffer.alloc(24, 0)` which sets `uncompLength` (length field at byte 16) to 0. Adding the tombstone filter `if (winner.length === 0) return undefined` caused the H1 binary-search test to return undefined (treat valid H1 entries as tombstones).
- **Fix:** Added `uncompLength = 1` default parameter to `makeEntry`; written at byte 16 so entries are non-tombstone by default.
- **Files modified:** `packages/renderer/src/services/tocReader.test.ts`
- **Committed in:** `5bdbc3d` (Task 1 GREEN commit)

**2. [Rule 2 - Missing Critical] treMount.ts tests (B)/(D) returned null after resolveLooseOverride implemented**
- **Found during:** Task 3 GREEN verification
- **Issue:** `vi.mock('fs')` in treMount.test.ts and `vi.mock('path')` were not being intercepted by treMount.ts because it used CJS `require('fs')` at module init — the Node CJS require cache is a different registry from Vite's ESM module graph.
- **Fix:** Changed `const nodeFs = require('fs')` to `import * as nodeFs from 'fs'` in treMount.ts and readVfsEntryBytes.ts. Same fix for nodePath.
- **Files modified:** `treMount.ts`, `readVfsEntryBytes.ts`
- **Committed in:** `a23e909` (Task 3 GREEN commit)
