## Findings (severity-ranked, reconciled to source)

### F-2 — BLOCKING (NO-GO). searchTOC extraction unwired in the UI. [Sonnet FM-2, verified]
`TreMount::resolve()` (`TreMount.cpp:176-210`) consults only each archive's internal TOC via
`node.archive->resolve()`; it never consults `m_externalEntries`. So for `patch_sku3_*`
(`numberOfFiles=0`) `resolve()` → not found. `readVfsEntryBytes` Case 3 (`extractMountAt` + descriptor)
is correct and unit-tested, but **the UI callers never supply the descriptor**:
- `TreVfsBrowser.tsx:222` (IFF viewer) and `:366` (Extract→Add) call `readVfsEntryBytes(entry, mountHandle)`
  with no descriptor → falls to Case 2 (`readMountEntry`) → `winnerEntryIndex = -1` → returns `null`.
- `openVfsEntry` (the descriptor-aware path, `openInViewer.ts`) has **zero callers** — dead code.
- `VfsEntry` carries no descriptor; nothing calls `tocIndex.resolveFull(entry.path)` at the open site.
**Effect:** searchTOC `patch_sku3`/v6000 files browse but silently fail to open/extract. Classic
executor-integration-blind-spot (service tests green, integration dead).
**Fix (loop back to plan 11):** at the TreVfsBrowser open/extract sites, when the winner is TOC-sourced,
call `tocIndex.resolveFull(entry.path)` and pass the descriptor to `readVfsEntryBytes`; and/or route the
viewer through `openVfsEntry` with the descriptor. Add an integration test that opens a TOC-external entry.

### F-3 — MEDIUM. shadowCount / isOverride inflation. [Sonnet FM-3]
`vfsEntriesColumnar` (`TreMount.cpp:514-568`) dedups an archive's internal entries AND its external
entries into the same `indexByPath` map. Archives with non-empty internal TOCs get every path counted
twice for the same `archiveIndex`, inflating `shadowCount` and falsely setting `isOverride=true` across
the searchTOC mount (wrong MountedArchivesList override display). Fix: dedup internal+external per
archiveIndex before shadow/override accounting.

### F-4 — LOW (robustness). Encrypted false-positive guard weaker than the oracle. [Opus]
Per-payload classify is correct for the locked axioms (SWG-Source plain zlib → readable; encrypted →
refused via RFC1950 header gate, ~95.6% + `Z_DATA_ERROR`). But for `compressor==2` the native strips the
4-byte Adler-32 and raw-inflates (`Zlib.cpp:93-95`), so zlib never validates it; `extractAt` adds no
CRC-32/length check (`TreArchive.cpp:382-393`). The `.toc` `crc` is parsed & stored
(`tre_binding.cpp:1187`) but never threaded into `TreExtractDescriptor` (`TreArchive.h:37-41`).
False-positive ≈10⁻³–10⁻⁵ per encrypted payload (only affects Restoration encrypted archives).
Fix: thread `crc` into the descriptor; after inflate require `CRC-32(0x04C11DB7)==desc.crc && produced==desc.length`.

### F-5 — LOW (latent). int32 narrowing of offset/length/compressedLength. [Codex]
`offset/length/compressedLength` read as `uint32` then narrowed to signed `int32` (`Int32Value`,
`tre_binding.cpp:1238`; engine uses `uint32`, `TreeFile_SearchNode.h:294`). No effect on real sku3
offsets; high-bit (>2GB) values would be mishandled. Fold into the F-4 descriptor fix (widen fields).

### F-6 — LOW (edge). Only `tocTreePaths[0]` passed to parseTocIntoMount. [Sonnet FM-1]
`autoMountClient` passes `order.tocTreePaths[0]` (`treAutoMount.ts:173`) but `buildTreNodes` tries all
prefixes (`:85-98`). A TRE found under `tocTreePaths[1]` gets zero external entries injected. Not
triggered on single-TOCTreePath installs (common case). Note / guard.

### F-7 — LOW (benign divergence). Tombstone semantics. [Sonnet FM-4]
As-merged flags `ext.length==0` external entries `isTombstone=true`; engine `SearchTOC::exists()` always
sets `deleted=false` (length==0 = "not found", not a stop-search tombstone; `TreeFile_SearchNode.cpp:840`).
Benign if master `.toc` has no length==0 entries. Note.
