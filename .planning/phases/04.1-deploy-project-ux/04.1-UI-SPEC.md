> Visual and interaction contract for the Deploy & Project UX redesign. Generated by gsd-ui-researcher,

>

## Spacing Scale

> **EXCEPTION — this project uses a 3px DCC base grid, NOT the GSD-default 8-point scale.** This is the
> established, shipped token system (`default.css`) for a Blender-style 3D-DCC tool optimized for compact
> density. The 8-point assumption in the GSD template does **not** apply here. All new spacing MUST use
> these existing tokens; do not introduce 4/8/16px literals.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 3px | Icon/glyph gaps, badge internal gap, tightest inline padding |
| `--space-2` | 6px | Compact element spacing, row gaps, button gaps |
| `--space-3` | 9px | Wizard/dialog internal stacking, section gaps |
| `--space-4` | 12px | Default panel/section padding, panel-head horizontal padding |
| `--space-6` | 18px | Larger group separation inside wizard steps |
| `--space-8` | 24px | Major section breaks (empty-state / first-run blocks) |

Fixed chrome dimensions (locked — reuse, do not redefine):
- `--tabstrip-h: 30px` (tab strip / panel-head height) · `--statusbar-h: 22px` · `--titlebar-h: 30px` · `--activity-w: 46px`
- Staging / version / delta **row height = 30px** (`ROW_HEIGHT`, matches `VfsTree`/`HexInspector`/`StagingPanel` — virtualization is mandatory; never change).
- Radii: `--radius-sm: 3px` (rows, buttons, inputs, chips) · `--radius-md: 6px` (modals, cards).

Width contracts (sketch 008, locked):
- Right dock default (Inspect active) ≈ **290px**.
- Right dock auto-widens to **~440px when the Deploy tab activates** (D-14 / 008-B); reverts on switching back to Inspect.
- **~300px narrow fallback** (008-C): labels/paths ellipsize, source-size column drops, the two per-row hover actions collapse to a single `⋯` overflow.

Exceptions: the 3px-grid deviation above (whole-phase). Modal/wizard fixed widths: deploy modal **360px**, single-input modal **440px**, wizard **~520px** (flagged assumption — see below).

## Typography

> Existing token scale (`default.css`). Two weights only: **400 (regular)** and **600 (semibold)**.
> Mono is reserved for machine text (virtual paths, file paths, cfg slots, counts, host:port, EERT
> version). Sans for all prose/labels/buttons.

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Body / prose | 13px | 400 | 1.5 | `--text-base` |
| Label / mono path / count / chip | 11px | 400 (600 for section labels) | 1.4 | `--text-xs` |
| Control / row text / dialog body | 12px | 400 | 1.4 | `--text-sm` |
| Heading (panel title, modal title, step title) | 14px | 600 | 1.2 | `--text-md` |

Conventions:
- Section sub-labels (e.g. "TARGET CLIENT", "DEPLOY MODEL", "PROJECT BINDING"): `--text-xs`, weight 600, `letter-spacing: 0.03em`, `text-transform: uppercase`, color `--color-text-muted` (existing `sectionLabelStyle`).
- All virtual paths, real file paths, cfg slot previews, counts, `host:port`, and `EERT<version>` render in `--font-mono`.

## Color

> 60 / 30 / 10 mapped onto the existing dark token system. Accent (cyan default) is theme-switchable —
> reference vars, never hexes.

| Role | Value (cyan default) | Token | Usage |
|------|----------------------|-------|-------|
| Dominant (60%) | `#181818` | `--color-bg` | App background, viewport, dock background, cfg-preview `<pre>` background |
| Secondary (30%) | `#242424` / `#2b2b2b` / `#323232` / `#3a3a3a` | `--color-surface`, `--color-surface-2`, `--color-header`, `--color-widget` | Panels, dialog/wizard surfaces, panel-heads & footers, tab strip, row hover (`surface-2`), widgets/inputs |
| Accent (10%) | `#38bec9` | `--color-accent` (+ `-hover`/`-text`/`-dim`/`-line`) | See reserved-for list |
| Destructive | `#e0584f` | `--color-danger` | Destructive confirmations + invalid/error inline text only |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The single **primary CTA per surface**: `Deploy <version>…`, `Save version`, `＋ Project` split-button, wizard `Create project` / `Next`, `Open Project…`.
2. The **selected / active state**: active dock tab underline (`.ptab.active::after`, 2px accent), selected version-graph node ring, selected radio option ring + `--color-accent-dim` fill (client picker, deploy-model cards), focused-input border.
3. **Resolve-chain override pips** indicating the project patch shadows a base TRE (reuse existing VfsTree pip).
4. **Progress / success affirmation** glyphs (`⟳ building…`, `✓ packed`, `✓ deployed`).
5. Focus ring (`--focus-ring`) and the active dockview sash (`--dv-active-sash-color`).

**Secondary semantic colors (existing tokens — used sparingly, always triple-encoded):**
- `--color-info` `#4a8cff` — `add` action badge glyph; informational path/echo lines (e.g. detected install path, ".include never touches user.cfg").
- `--color-warn` `#e0a13a` — `delete (tombstone)` badge; `⚠ source missing`; hardlink-full-shadow disk-space caution; stale-deployment banner; "unconfirmed directory" warning card.
- `--color-text-muted` `#9a9a9a` — `modify` action badge glyph; secondary labels.
- `--color-danger` — destructive confirmation buttons, invalid-path / build-error text.

Change-vs-base dot (006-D, all delta rows): `●` filled = content differs (`--color-accent` or `--color-text` per existing pip), `○` hollow faint = identical-to-base no-op (`--color-text-faint`, row dimmed `opacity ~0.55`, "identical to base" tag). Never color-only — glyph shape + tag carry it.

## Surface Contracts

### Surface 1 — Combined Deploy panel (DEPLOY-05; sketches 005-B / 006-D / 008)

One `DeployPanel` inside the right dock's `Inspect | Deploy` two-tab group. Activating `Deploy` auto-widens the dock to ~440px.

Vertical anatomy (top→bottom):
1. **Working changes** (collapsible accordion section). Header row: title `Working changes` + `Add` (secondary) + `Save version` (primary accent, disabled until ≥1 change). Body = 30px virtualized rows: `ActionBadge | ●/○ changed-or-identical dot | virtual path (mono, flex 1, ellipsis) | source · size (drops <~320px) | hover actions`. Hover/`⋯` context menu at TRE-view parity: **Open in editor · Open in viewport · Reveal in TRE browser · Compare to base · Remove from staging**. Footer counts: `N staged · A add · M modify · D delete` + `C changed · I identical`.
2. **Splitter** — draggable divider balancing staging-heavy vs history-heavy; auto-hidden when either section is collapsed.
3. **Version history** (collapsible accordion section). Git-graph lanes (002-A) with a dashed-square **Baseline (pristine)** root node ("0 deltas · shadow ≡ source", action "Deploy (reset to stock)"). Each version row expands `▸` to list that changeset's `deltas[]`: `ActionBadge | ●/○ dot | virtual path`. Selecting a version sets the Deploy target and re-materializes staging (`flatten(active)`). Node pips: `● active`, `⤓ live · deployed`, dashed `baseline` — glyph + border + label, never color-only. Row hover: inline `Revert · Deploy vN · Branch from here` (collapse to `⋯` at narrow width).
4. **Sticky footer CTA** — `Deploy <selected version>…` (accent). Opens the `DeployDialog` modal (zero panel space). Deploy operates on `flatten(activeVersionId)`, **never** the live staging list.

Narrow (~300px) fallback: paths/labels ellipsize, source-size column hidden, per-row actions collapse to single `⋯` overflow popover, Baseline node + expandable deltas remain legible.

Tab chrome scroll-fix (honor exactly, from the chrome kit / 008): `.panel-tabs { overflow-x: auto; overflow-y: hidden; }` and the active-tab underline at `.ptab.active::after { bottom: 0; height: 2px; background: var(--color-accent); }`.

### Surface 2 — Project front door (PROJ-01; sketch 007 synthesis)

Three composed pieces:
- **Persistent header control (007-A):** equal-width `＋ Project ▾` split-button (menu: New · Open… · Open Recent) **beside** `Mount Archive…` in the Assets `.panel-head`. When bound, a project bar shows the project name + bound-client chip `⛁ <client> · EERT<version>` and a populated tree.
- **New-Project wizard (007-C):** single-column stepper modal over a dimmed shell (reuses the 003 overlay pattern). Steps:
  1. **Name & location**
  2. **Bind client** — auto-detected installs as radio rows + `Browse for client folder…`. Includes the **unconfirmed-directory branch** (Surface 3).
  3. **Local server (optional) — CAPTURE ONLY (D-01):** "Are you running a local server for this project?" Yes/No. Yes reveals **type** (Core3 / WSL2 · SWG Source / Docker), **path**, and **host:port** (placeholder `127.0.0.1:44463`). Stored + surfaced in the inspector's *Project binding* group. **No server-push UI** in 4.1.
  4. **Seed assets** — bound client's TRE set (recommended) vs start empty.
- **First-run / empty state (007-B):** Assets-panel welcome takeover — Recent projects, an auto-scan "Detected clients" list with `✓ ready` / `✗ not found` pills (glyph + border + label), and large New / Open / Mount actions. Viewport/Inspector/data panes dimmed until a project loads.

Non-client projects are first-class: a project may have no bound client (deploy-to-client disabled; assets/server-only).

### Surface 3 — Client detection surfacing + manual override (D-13)

In the wizard's Bind-client step and the inspector's *Project binding* group, **show what was detected** for confirm/correct:
- cfg path + filename (varies: `swgemu.cfg` / `client.cfg` / …), TRE dir (`Live/` subfolder vs install root), matched release pattern, `maxSearchPriority` (Infinity = 60, SWGEmu = 27).
- A **manual-override** entry: user types the actual cfg path/name + TRE dir when auto-detect can't classify. Override persists with the binding.
- **Unconfirmed-directory branch:** if the browsed folder can't be confirmed (no EERT TRE set / no client exe), show a `--color-warn` warning card asking **"Is this a client install?"** → **Yes, treat as client** (deploy enabled, user-confirmed) or **No, non-client project** (no bound client; deploy disabled).

### Surface 4 — Stage-from-TRE-browser (DEPLOY-07)

Extract→Add directly from the VFS browser into staging — **no manual virtual-path entry**. The virtual path is derived from the browsed entry's path; the existing `VirtualPathModal` prompt path is retired from the Add-from-browser flow. The staging empty-state copy must be corrected so it describes the real browser-driven flow (see Copywriting — the current "Extract a file and Add to patch" implies a flow that today still prompts for a manual path).

### Surface 5 — Reset-layout / reopen-closed-panel affordance (DEPLOY-07; D-03)

- Lives in the **View / window menu** (and/or a status-bar "reset layout" control) — discoverable, not buried.
- Behavior: clears the **stale persisted dockview layout** (bump the layout-version key; discard any saved layout referencing the retired `staging`/`changesets`/`vcs` panel ids) and rebuilds to the **008 default** (Assets · Viewport · Inspect|Deploy group · VCS · data pane). Also fires automatically on layout-version mismatch (no soft-brick).
- Reopen-closed-panel: a menu list of closed panels to re-add to the dock.

### Surface 6 — Deploy modal states (DEPLOY-06; `DeployDialog`)

- **Target client:** auto-selects the bound client so `Deploy patch` is **enabled by default** (D-12) — fixes the "button looks broken" gating on `!selectedClient`. `Browse…` remains for override.
- **Deploy model (D-02 / D-05):**
  - **Default = absolute-path override `.tre` (no copy)** — registers `searchTree_<sku>_<NN>=<absolute path in .studio/build>`; retail files stay pristine. Selected by default (accent ring + `--color-accent-dim`).
  - **Opt-in = hardlink full-shadow ("throwaway isolated client")** — hardlinks unchanged base TREs into a same-NTFS-volume work dir + writes only the changed override; separate launch profile. Reveals a `--color-warn` `⚠ ~<N> GB free disk needed` / same-volume caution when selected. (Retire the old multi-GB physical-copy default.)
- **Phase states (single discriminated flow):** `idle` → `building` (`⟳ Building patch (v5000)…`) → `writing cfg` (`⟳ Writing client config…`) → `done` (`✓ deployed · slot <N>`) → `error` (`✕` + cause + "the .cfg was restored from backup", with Retry). `Reset deployment` restores the snapshotted original cfg from `.studio` (whole-file restore, D-07) — confirmation copy below.

## Accessibility (Rule 1 — state never by color alone)

- Every action / state cue is **glyph + color + text**: action badges, change/identical dots, node pips (`● active` / `⤓ live · deployed` / dashed `baseline`), detected-client pills, deploy phase states.
- Global focus ring `--focus-ring` on all interactive elements; high-contrast theme provides a thicker ring + visible borders.
- Modals: `role="dialog" aria-modal="true"`, Esc closes, backdrop click cancels, autofocus first input.
- Lists virtualized with `role="listbox"` / `role="option"` (staging) — preserve when extracting `StagingPanelBody`.
- All copy must remain legible under the high-contrast theme; verify pills/badges/pips there.
