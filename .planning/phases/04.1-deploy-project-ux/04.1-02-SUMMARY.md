## What Was Built

**`projectBinding.ts`** — PROJ-01 front door service:
- `detectFolderKind(folder)` — classifies folder as `'client'` (cfg + .tre files), `'tre-set'` (.tre only), or `'mod-project'` (neither). Probes `swgemu.cfg`/`client.cfg` + `Live/` subdir pattern matching clientLocator.ts.
- `readWorkspaceJson(studioDir)` — reads `.studio/workspace.json`, returns safe defaults on absence/parse failure.
- `writeWorkspaceJson(studioDir, meta)` — atomic tmp+rename write (T-04.1-02: only writes under studioDir).
- `initProject(folder)` — detect → mkdirSync studioDir → write workspace.json → `openWorkspace(folder)` → if client, enumerate `.tre` files from treDir and call `mountTrePaths` with ascending 1-based priorities (M5: unconditional for client-kind, no wizard gate).

**`treMount.ts`** — extracted shared mount routine:
- `decodeMountEntriesColumnar(blob)` — moved verbatim from TreVfsBrowser private fn; now exported (H3 fix — both manual mount path and projectBinding share one owner).
- `mountTrePaths(filePaths, priorities)` — calls `mountSearchableAsync`, maps `getMountArchives`, decodes columnar blob, calls `treStore.mountComplete`.
- Uses **named ESM `import`** for `@swg/native-core` (key design decision — see Deviations).

**`workspaceService.ts`** — persistence wiring:
- `openWorkspace`: inline-reads `.studio/workspace.json`, passes real `clientPath`+`kind`+`cfgPath`+`treDir` to `openComplete` instead of hardcoded `null`/`'mod-project'`.
- `createWorkspace`: same inline-read pattern (defensive — covers pre-bound folder case).
- No circular import: workspaceService reads JSON inline, does NOT import from projectBinding.

**`packages/native-core/index.d.ts`** — added missing declaration:
- `getMountEntriesColumnar(handle)` was exported in `addon.cpp` but missing from TypeScript declarations.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `vi.fn<[], T>()` TypeScript 6.0 incompatibility**
- **Found during:** Task 1 (RED authoring)
- **Issue:** `vi.fn<[], Promise<string>>()` — TypeScript 6.0 changed `vi.fn` to accept 0-1 type arguments, not 2
- **Fix:** Removed explicit type parameters, used `vi.fn().mockResolvedValue(...)` without generics
- **Files modified:** `projectBinding.test.ts`
- **Commit:** 15b522a

**2. [Rule 3 - Blocking] `tsconfig.json` rootDir/test file boundary**
- **Found during:** Task 1 (RED compile)
- **Issue:** `projectBinding.test.ts` (in `src/`) imports `../../test/fixtures/fakeClientDir.ts` (outside `src/`); `tsc` reported `TS6059: not under rootDir 'src'`
- **Fix:** Excluded `src/**/*.test.ts` and `src/**/*.test.tsx` from `tsconfig.json`; vitest handles test file compilation via Vite, not `tsc`
- **Files modified:** `packages/renderer/tsconfig.json`
- **Commit:** 43cc562

**3. [Rule 1 - Bug] `require('@swg/native-core')` bypasses vitest mock registry for native addons**
- **Found during:** Task 3 (GREEN — tests still failing despite implementation)
- **Issue:** `vi.mock('@swg/native-core', factory)` hooks ESM import resolution, NOT CJS `require()`. The native addon's `index.js` uses `module.exports = dlopen(...)`, so `require('@swg/native-core')` inside `treMount.ts` bypassed vitest's mock registry and called the real C++ `mountSearchableAsync` with 8-byte stub .tre files, producing: `TreArchive::parse: stream too short for TRE header (need 36 bytes)`
- **Fix:** Changed `treMount.ts` from `const nativeCore = require('@swg/native-core')` (module scope CJS) to named ESM imports: `import { mountSearchableAsync as nativeMountSearchableAsync, ... } from '@swg/native-core'`. Vitest intercepts ESM import resolution and returns the mock factory's result.
- **Files modified:** `packages/renderer/src/services/treMount.ts`
- **Commit:** 25b8858

**4. [Rule 2 - Missing] `getMountEntriesColumnar` undeclared in `@swg/native-core` type declarations**
- **Found during:** Task 3 (TypeScript compile after ESM import switch)
- **Issue:** `TS2305: Module '@swg/native-core' has no exported member 'getMountEntriesColumnar'` — the function was exported in `addon.cpp` and `tre_binding.cpp` (added as the perf fix for the >1min freeze) but never added to `index.d.ts`
- **Fix:** Added full declaration with binary layout documentation to `packages/native-core/index.d.ts`
- **Files modified:** `packages/native-core/index.d.ts`
- **Commit:** 25b8858

**5. [Rule 1 - Bug] `decodeMountEntriesColumnar` DataView RangeError on minimal-stub buffers**
- **Found during:** Task 3 (tests after ESM mock fix — second error revealed)
- **Issue:** Function read `archPathDataOffset = buf.getUint32(12, true)` BEFORE the `if (entryCount === 0) return []` guard. The mock returns `new ArrayBuffer(8)` (8 zero bytes). entryCount=0 but offset 12 is out of bounds → `RangeError: Offset is outside the bounds of the DataView`
- **Fix:** Moved `if (entryCount === 0) return []` immediately after reading `entryCount`, before reading remaining header fields
- **Files modified:** `packages/renderer/src/services/treMount.ts`
- **Commit:** 25b8858
