# Phase 04.1 Plan 07: Zero-Risk Shadow Re-Architecture + snapshotCfg/restoreCfg + DeployDialog Rewire Summary

**fs.promises.link hardlink path with same-volume guard + whole-file ROOT-cfg snapshot/restore + absolute-path default deploy model + Baseline-reset routing + auto-rollback + cross-session Reset.**

## Accomplishments

- `snapshotCfg(rootCfgPath, studioDir)` — new cfgActivator export: copies ROOT cfg (swgemu.cfg, the file `ensureInclude` mutates) to `.studio/snapshots/<basename>.bak` BEFORE the first mutation; idempotent (second call returns existing path without overwriting; preserves pristine pre-mutation content)
- `restoreCfg(rootCfgPath, snapshotPath)` — new cfgActivator export: atomic tmp+rename whole-file restore; removes `.include` + any maxSearchPriority bumps written by activatePatch; client becomes byte-pristine
- `activatePatch` idempotent `[SharedFile]` header — `needsHeader = !existing.includes('[SharedFile]')`: second deploy no longer adds a duplicate section header (Pitfall 4 fix)
- `activatePatch` optional `studioSnapshotDir` — backup written into `.studio/snapshots` when provided; falls back to next-to-cfg for legacy callers
- `sameVolume(a, b)` — new shadowBaseService export: `fs.statSync(a).dev === fs.statSync(b).dev`
- `deployShadowBase` hardlink loop — `fs.promises.link` per TRE when `canLink=true`; EXDEV→`copyFile` per-file fallback; W4 containment guard before each link
- `deployShadowBase` disk check guard — `checkFreeDisk` called only when `!canLink` (hardlinks consume ~0 extra bytes); `sameVolume` computed before `estimateTreSize` to skip it entirely on the hardlink path
- `deployShadowBase` relocated backup — `.shadow.bak` now in `.studio/snapshots` (D-06/D-07); never in client install tree
- `deployShadowBase` EMPTY swgtoolkit.cfg — creates `''` not `'[SharedFile]\n'`; `activatePatch` is sole header writer
- `deployShadowBase` adds `ensureInclude(cfgRootPath)` call — M9 fix; shadow path was missing this call so root cfg never learned about swgtoolkit.cfg
- `DeployDialog` deploy model — default `'absolute-path'` (D-05); opt-in `'hardlink-shadow'`; Section B UI labels updated; disk note updated for hardlink context
- `DeployDialog` H1 Baseline routing — `manifest.activeVersionId === BASELINE_ID || flattenedEntries.length === 0` → `restoreCfg` + delete toolkit cfg + delete patch + `setDeployedVersion(null)` → phase done ("Baseline reset to stock"); bypasses the confusing length=0 error
- `DeployDialog` snapshotCfg before mutation — both paths call `snapshotCfg(cfgRootPath, studioDir)` before the first cfg mutation; snapshot path persisted in `CfgDeployRecord.snapshotPath`
- `DeployDialog` H5 handleReset — `restoreCfg` as PRIMARY for ALL models; model-specific artifact cleanup (shadow dir rmSync / patch .tre unlink) after restore; deactivatePatch/resetShadow as fallback when no snapshot
- `DeployDialog` H5/M9 auto-rollback — both paths catch errors and call `restoreCfg` if snapshot available; `cfgRestored` flag set accurately; error message updated
- `DeployDialog` M8 cross-session Reset — on dialog open, `readManifest` and load `cs.deployRecord` into `deployRecordRef` so Reset works after close/reopen
- `CfgDeployRecord.snapshotPath?: string` — new optional field in contracts; backwards-compatible
- `DeployModel` type in contracts — updated to include `'absolute-path' | 'hardlink-shadow'` (legacy names kept for compat)

## Decisions Made

- `snapshotCfg` is idempotent per-deploy (no overwrite) — the first snapshot captures the PRE-MUTATION (pristine) ROOT cfg; a second deploy must NOT overwrite or the pristine backup is lost
- `sameVolume` computed BEFORE `estimateTreSize` — allows completely skipping `estimateTreSize` (a readdirSync + statSync loop over all TREs) on the hardlink path where disk space is irrelevant
- `absolute-path` as default (D-05) — writes the absolute path to `.studio/build/<patch>.tre` as the searchTree value; no copy to Live/; TreeFile.cpp absolute path support is an existing UAT item
- `swgtoolkit.cfg` created EMPTY — prevents the duplicate `[SharedFile]` header that the old `'[SharedFile]\n'` init + `activatePatch`'s unconditional header caused
- `handleReset` PRIMARY = `restoreCfg`, fallback = line-surgery — ensures backwards compatibility with pre-07 deploy records that lack `snapshotPath`; whole-file restore is always preferred when the snapshot exists
- D-09 (pluggable TRE codec) — deliberate NO-OP this phase; noted in plan; existing TRE codec reused as-is

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] ensureInclude missing from deployShadowBase (M9)**
- **Found during:** Task 3 implementation review
- **Issue:** The plan's M9 item required `ensureInclude` on BOTH deploy paths. The shadow/hardlink path called `deployShadowBase` from DeployDialog but `deployShadowBase` itself never called `ensureInclude(cfgRootPath)`. The shadow TRE cfg entries are written to swgtoolkit.cfg, but without `.include "swgtoolkit.cfg"` in the ROOT cfg, the client never reads swgtoolkit.cfg.
- **Fix:** Added `ensureInclude(client.cfgRootPath, 'swgtoolkit.cfg')` inside `deployShadowBase`, after the toolkit cfg creation and backup; also updated the cfgActivator mock in shadowBaseService.test.ts to add `ensureInclude: vi.fn()`
- **Files modified:** `shadowBaseService.ts`, `shadowBaseService.test.ts`
- **Verification:** 73/73 tests pass; tsc clean

**2. [Rule 3 - Blocking] cfgActivator mock missing ensureInclude (caused import error)**
- **Found during:** Task 3 test run
- **Issue:** After adding `ensureInclude` import to shadowBaseService.ts, the `vi.mock('./cfgActivator', ...)` in shadowBaseService.test.ts only mocked `activatePatch`. The missing `ensureInclude` mock caused the real cfgActivator to try loading fs (not mocked at that point in the import chain), which could have caused issues.
- **Fix:** Added `ensureInclude: vi.fn()` to the cfgActivator mock factory
- **Files modified:** `shadowBaseService.test.ts`

**3. [Rule 1 - Bug] Stale contracts dist prevented TypeScript from seeing snapshotPath**
- **Found during:** Task 3 tsc check
- **Issue:** `tsc -p packages/renderer/tsconfig.json --noEmit` reported `Property 'snapshotPath' does not exist on type 'CfgDeployRecord'` — the renderer uses the compiled `dist/index.d.ts` from contracts via project references; this was stale
- **Fix:** Built contracts first (`npx tsc -p packages/contracts/tsconfig.json`) to regenerate `dist/*.d.ts`; dist is gitignored so this just updates local state
- **No files committed:** dist is in .gitignore; build step is needed before type checking
