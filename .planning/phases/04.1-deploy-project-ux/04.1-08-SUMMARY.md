- Passes `onExtract={handleExtract}` to `<VfsTree />`

## Deviations from Plan

### Auto-added Missing Critical Functionality

**1. [Rule 2 - Missing Critical] VfsTree.tsx modified (not in plan's files_modified)**
- **Found during:** Task 2 (implementing Extract→Add)
- **Issue:** Extract→Add requires a per-row hover action inside VfsRow (VfsTree.tsx). The plan lists `TreVfsBrowser.tsx` as the entry point but VfsTree renders the rows. Without modifying VfsTree.tsx, the only options were: (a) context-menu overlay on the outer container (can't know which row was right-clicked without a prior left-click), or (b) a selected-entry toolbar button (discoverable but not "per-row"). The hover-button pattern is the canonical UI-SPEC "row hover" variant (plan task 2 says "context menu (and/or row hover)").
- **Fix:** Added optional `onExtract?: (entry: VfsEntry) => void` prop to VfsTree + VfsRow. Hover button renders only when prop is set (backward-compatible). All existing VfsTree consumers continue to work without the prop.
- **Files modified:** `packages/renderer/src/panels/tre/VfsTree.tsx`
- **Commit:** 78460f7
