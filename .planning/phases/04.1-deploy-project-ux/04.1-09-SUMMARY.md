## Decisions Made

- **KNOWN_LAYOUTS probe order**: Infinity (Live/ subdir) first, SWGEmu (root) second. An Infinity install has swgemu.cfg at root AND Live/ subdir with TREs. If SWGEmu pattern were tried first it might match on the root cfg but then fail to find TREs (they're in Live/, not root), so null would be returned — misclassifying a valid Infinity install. The Infinity pattern is checked first to avoid this.
- **resolveLayout returns null for unknown layouts, no internal fallback**: consumers are responsible for surfacing the manual-override UI. This keeps the resolver pure and testable.
- **ClientLayout as unified carrier**: both auto-detected and user-entered overrides use the same type; `release: 'manual'` distinguishes user-entered entries.
- **M4: ProjectBindingBar is the single canonical home**: per the plan's M4 note, the binding-details sub-row lives ONLY in ProjectBindingBar, NOT also in a separate inspector accordion.
