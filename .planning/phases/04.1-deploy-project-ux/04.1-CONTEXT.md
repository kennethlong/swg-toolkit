# Phase 04.1: Deploy & Project UX - Context

**Gathered:** 2026-06-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the **already-working** deploy loop **discoverable and zero-risk** by building the **approved
sketch designs** (005-B / 006-D / 007 / 008) — this is UI/UX composition + a project↔client binding
workflow + a shadow-model re-architecture, **NOT** new byte-level format work. The Phase-4 deploy
**engine** (`packPatch`, `changesetService` flatten/seal/select, `cfgActivator`, `shadowBaseService`,
`DeployDialog`, `gitLfsService`, `workspaceService`) is **reused as-is**; this phase changes how it is
*composed, surfaced, and defaulted*, plus connects the project to a bound client.

**In scope:**
- **Project↔client binding front door** (PROJ-01): open/create a project → detect whether the folder is
  a client install → mark `kind: client|tre-set|mod-project`, auto-bind `clientPath`, auto-mount that
  client's base TREs into the TRE VFS browser. Project entry point in the Assets tab (next to
  `Mount Archive…`) + the 007 header front door + New-Project wizard.
- **One combined Deploy tab** (DEPLOY-05): staging (working changes) over the version graph
  (per-node expandable changed-file lists) + `Deploy…` modal CTA, vertically stacked in a single
  `Inspect | Deploy` dock group (sketch 005-B/006-D/008). Replaces the shipped 3-tab split
  (`Staging`/`Changesets`/`Version Control`). VCS stays its own tab (separate axis).
- **Lazy/virtual shadow re-architecture** (DEPLOY-06): default = **absolute-path override `.tre`,
  no copy** (verified accepted); **plus** an opt-in **hardlink full-shadow** ("throwaway isolated
  client"); retire the copy-into-client default AND the multi-GB physical copy. Undo = restore the
  snapshotted original cfg from `.studio`. Baseline changeset root node at project creation.
- **Client detection + manual override** (cfg filename + TRE dir vary across releases).
- **Stage-from-TRE-browser** (DEPLOY-07): Extract→Add path, no manual virtual-path entry.
- **Reopen-closed-panel / reset-layout** affordance (DEPLOY-07) + clearing the stale persisted dock
  layout on version mismatch.
- **Local-server association — CAPTURE ONLY** (007 wizard step 3): store server type/path/host:port +
  surface in the project-binding group. **No server push** (that is Phase 8).
- **Missing Save-version action** + **duplicate `[SharedFile]` header** cfg bug + **centralize IPC
  channel types** (folded supporting todos).

**Out of scope (boundaries):**
- **Server-side TRE push / registration** → Phase 8 (server TRE search-path is unverified ground-truth;
  only *capture* the server config here).
- New byte-level format work / typed editors (DTII grid, `.stf`, gizmo) → Phase 5.
- v6000 / encrypted TRE content → out of scope (pluggable-codec extension point only; memory
  `tre-version-oracles-and-v6000-encryption` confirmed correct: 6000 = Restoration proprietary-encrypted).

</domain>

<decisions>
## Implementation Decisions

### Discussion resolutions (this session, 2026-06-27)
- **D-01 — Server scope = CAPTURE-ONLY.** Include the 007 wizard's optional local-server step (store
  type [Core3/WSL2 · SWG Source/Docker], path, `host:port` e.g. `127.0.0.1:44463`) and surface it in
  the inspector's project-binding group. **No server push** in 4.1 — server-side TRE registration is
  Phase 8 (gated on the still-open server TRE search-path verification).
- **D-02 — Full shadow = INCLUDE hardlink full-isolation now.** Ship BOTH: (a) default absolute-path
  override `.tre` (no copy), and (b) opt-in **hardlink full-shadow** ("throwaway isolated client":
  hardlink unchanged base TREs into a work dir on the same NTFS volume + write only the changed override;
  separate launch/config profile). Retire the model-C multi-GB physical copy.
- **D-03 — Persisted layout migration = CLEAR (maintainer confirmed "safest path").** Bump a layout
  version; discard any saved Dockview layout that references the old `staging`/`changesets`/`vcs` panel
  ids so the dock rebuilds to the 008 vertical-stack default. Pure technical cleanup, no design impact;
  pairs with the new reset-layout affordance.
- **D-04 — Slice order = FRONT-DOOR + CENTERPIECE FIRST.** Slice 1: project↔client binding + auto-mount
  + combined Deploy tab (the visible win). Slice 2: shadow re-arch (absolute-path default + hardlink
  opt-in, retire copy) + baseline changeset node. Slice 3: stage-from-TRE + client-detection/override +
  reset-layout + local-server capture + cfg `[SharedFile]` fix.

### Shadow / deploy model (settled in todos, locked here)
- **D-05:** Default deploy model = **absolute-path override `.tre`** in `.studio/build`, registered via
  `searchTree_<sku>_<NN>=<absolute path>`. **Verified accepted** vs real `swg-client-v2`
  (`TreeFile.cpp:130-138`/`360-372`, `TreeFile_SearchNode.cpp:249-264`, `OsFile.cpp:86` — value used
  verbatim → `CreateFile`, no base-dir prepend; priorities search high→low).
- **D-06:** **Constraint — `.studio` MUST be at a whitespace-free absolute path** (ConfigFile truncates a
  `searchTree` value at the first space; `D:\SWG Infinity\…` would break). `.studio` lives **under the
  app root**, NOT inside the client.
- **D-07:** **Client stays pristine** — zero toolkit files written into the client install except the
  live `.cfg` edit. The cfg backup moves from next-to-cfg into `.studio/`. **Undo = copy the snapshotted
  original cfg back** (whole-file restore) for ALL deploy models — supersedes line-surgery as the primary
  reset path.
- **D-08:** **Baseline changeset** — seed the version graph at project creation with a `Baseline` root
  node, zero deltas (pristine = shadow == source). Guaranteed graph root; "reset to stock" = select
  Baseline → deploy (empty override). Deliberate add to `createWorkspace`/`changesetService`.
- **D-09:** **Pluggable TRE read/write codec interface** (extensibility for forks with custom
  compression/encryption) — architecture constraint, not a feature to ship UI for.

### Project binding & detection (settled in todos, locked here)
- **D-10:** Persist `clientPath` + `kind: 'client' | 'tre-set' | 'mod-project'` in the workspace
  manifest/`workspace.json`. On open/create, **detect** if the folder is a client install (cfg `.include`
  chain / client exe / `Live/`), mark + auto-bind. (`WorkspaceInfo.clientPath` is currently always null.)
- **D-11:** **Auto-mount** the bound client's base TREs into `treStore`/`TreVfsBrowser` on open (reuse
  `mountSearchableAsync` + the `.include`/search-tree scan in `clientLocator`/`cfgActivator`), with the
  project's override layered so resolve-chain override pips render the patch shadowing the base.
- **D-12:** **`DeployDialog` auto-selects the bound client** so "Deploy patch" is enabled by default
  (today it gates on `!selectedClient` and never auto-selects → button looks broken).
- **D-13:** **Pattern-detect client layout, with manual override.** cfg filename varies
  (`swgemu.cfg` / `client.cfg` / …), TRE dir varies (`Live/` subfolder vs install root),
  `maxSearchPriority` varies (Infinity=60, SWGEmu=27). Build a small release-pattern table; let the user
  enter the actual cfg path/name + TRE dir when auto-detect can't classify; persist override with the
  binding; surface what was detected for confirmation.

### Combined Deploy tab (sketch-settled)
- **D-14:** One `DeployPanel.tsx` vertically stacking: (1) staging body, (2) version-graph body
  (rows expand ▸ to list that changeset's `deltas[]` — action badge + changed/identical dot + virtual
  path), (3) `Deploy…` CTA → existing `DeployDialog` modal. Extract `StagingPanelBody` + timeline body so
  they compose without duplicate panel headers/gates. Deploy operates on `flatten(activeVersionId)`,
  never the live staging list. `workspace-config.ts` replaces the `staging`+`changesets` panels with one
  `deploy` panel; `vcs` stays separate. Inspector auto-widens ~440px when Deploy active (008).
- **D-15:** Add the missing **Save version** action (seals via `sealVersion`) — `handlePackPatch` dead
  code; sealing must not depend solely on Deploy auto-seal.
