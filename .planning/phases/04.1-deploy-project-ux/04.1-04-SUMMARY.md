## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing] `initProject` lacked override options for M6 and D-01**
- **Found during:** Task 2 (NewProjectWizard implementation — wizard needs to pass overrideKind and serverConfig)
- **Issue:** `initProject(folder: string)` only accepted the folder; no way for the wizard to pass M6 kind override or D-01 serverConfig through the service layer. Without this, "Yes, treat as client" (M6) would be silently overridden by `detectFolderKind` on the next call.
- **Fix:** Added `InitProjectOptions` interface and optional second param; `initProject(folder, options?)` uses `options.overrideKind ?? detectFolderKind(folder)` and merges `options.serverConfig` into the persisted `WorkspaceBindingMeta`.
- **Files modified:** `packages/renderer/src/services/projectBinding.ts`
- **Commit:** 12e0632

## Known Stubs

- **Open Recent** in the ProjectBindingBar ▾ dropdown: disabled (aria-disabled, greyed out) — no recent-projects tracking exists in Phase 4.1. Plan 09 will add the full release-pattern/manual-override UI (D-13); recent projects tracking is deferred to that plan or later.
- **Step 4 seed-assets pre-population**: "Use client TRE set" selects the option but does NOT actually pre-populate the staging list (no seed logic exists this phase). M5 unconditional auto-mount IS implemented (projectBinding.initProject mounts TREs regardless); the staging-pre-populate is future work. The option is tracked in wizard state for future wiring.

These stubs do NOT prevent the plan's goal: ＋ Project / wizard / first-run all drive `initProject`; non-client projects are first-class; "treat as client" forces client kind; client TREs auto-mount; server is captured only.

## Threat Flags

None beyond the plan's threat model. T-04.1-07, T-04.1-08, T-04.1-09 mitigations confirmed:
- T-04.1-07 (Tampering — wizard folder/cfg inputs): All paths come from `workspace:pick-dir` IPC (OS dialog in main process), not free-text inputs. `projectBinding.initProject` normalizes via `path.resolve`.
- T-04.1-08 (Elevation — captured serverConfig): Stored as opaque strings in workspace.json; no connection or execution in Phase 4.1.
- T-04.1-09 (Spoofing — "treat as client" override): User confirms via the unconfirmed-directory branch UI; the override persists to workspace.json as `kind:'client'`; deploy stays disabled until `workspaceStore.clientPath` is set (which only happens for client kind via `initProject`).
