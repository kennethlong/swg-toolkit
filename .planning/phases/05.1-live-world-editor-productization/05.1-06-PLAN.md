**ROUND 4 REVISION (2026-08-01, REVIEWS.md W1 — HIGH, Sonnet; ROUND-4 DESIGN PICK, vetoable next round):**
R6 made the persisted FLAG atomic (`updateWorkspaceMeta` only fires when `failures.length === 0`), but the
per-building reconcile LOOP underneath it was not: on a mixed pass (building A's stock path known, building
B's unknown), the loop already wrote/deleted A's mirror on disk before reaching B's failure, so the flag stayed
unmoved while A's disk state moved anyway — disk and flag disagree for exactly the buildings that "succeeded,"
reopening the D-09 stale-override class one layer down. Task 1 below makes `reconcileMirrorMode` run in two
phases so writes/deletes for ANY building never happen unless the WHOLE pass is known-clean: **(1) validate
first, write never** — check every building's `buildingTemplateVfsPath` before touching disk; if any building
fails this check, return immediately with zero disk writes for ANY building, known or unknown; **(2) apply,
with rollback on a mid-pass throw** — only entered when validation is clean for every building; if a write/
delete unexpectedly throws partway through, undo (by re-applying the inverse operation) every building already
applied THIS call, so disk returns to its exact pre-call state, and no flag persist happens. **Design-pick
rationale (one sentence, reviewers may veto next round):** rollback-by-inverse-operation is chosen over
pre-materializing a full write buffer because a stock mirror file is always a deterministic byte-for-byte copy
of the building's already-in-memory edited `.ilf`, so "undo by re-deriving the opposite state" is exactly as
correct as "stage then commit" while requiring no new buffering machinery. This closes W1's literal repro (a
known-building + unknown-building mixed toggle-flip) at the disk level, not just the flag level; Plan 10's
history-entry wording and Plan 15's sign-off gain a step exercising this exact mixed pass (see those plans'
own ROUND 4 revisions).
