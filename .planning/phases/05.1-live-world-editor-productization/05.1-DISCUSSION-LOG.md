## Add/Remove plumbing semantics

**Q1 — When does persistence happen after the placement click (021-A)?**

| Option | Description | Selected |
|--------|-------------|----------|
| Place-then-adjust (Recommended) | Click spawns via wsAddObject and auto-arms the gizmo; nudge, then explicit Persist. Add = armed edit whose persist appends a row. One code path. | ✓ |
| Auto-persist on click | Placement click immediately runs the full persist; fastest for bulk but a misclick writes a row. | |
| Stage in panel, persist in batch | Placements accumulate as pending rows; one "Persist all". Diverges from the proven per-edit loop. | |

**Q2 — Which decorations can be removed?**

| Option | Description | Selected |
|--------|-------------|----------|
| Any decoration, incl. stock (Recommended) | Edited .ilf omits the row; stock file untouched; inherently reversible. | ✓ |
| Toolkit-added only | UI-imposed restriction the pipeline doesn't need. | |
| Any, but stock removals flagged | Struck-through removed-stock rows for discoverable restore. | |

**Q3 — Where is Remove triggered, and what guards it?**

| Option | Description | Selected |
|--------|-------------|----------|
| Panel action + undo toast (Recommended) | World-panel row action; no confirm; undo toast re-adds (DeleteUndoToast precedent). HUD stays pick/move/persist. | ✓ |
| Panel + in-game hotkey | Adds a destructive Delete key to the thin HUD. | |
| Panel + confirm dialog | Heavier than the app's undo-toast idiom. | |

**Q4 — If add/remove needs a provider shim, block or degrade?**

| Option | Description | Selected |
|--------|-------------|----------|
| Degrade to reload-verify (Recommended) | File change-request early; remove persists with "takes effect on scene reload" until the shim lands. | |
| Block the remove slice on the shim | Puts the relay loop on the critical path. | |
| Planner decides per finding | Research establishes need; planner picks per case with pre-wire/bind-by-name as default posture. | ✓ |

## World panel data spine

**Q1 — Source of truth for the building tree?**

| Option | Description | Selected |
|--------|-------------|----------|
| Disk scan + session overlay (Recommended) | Scan override dir (edit_*.ilf + derived templates), diff vs stock; live state overlays while attached; works offline. | ✓ |
| Toolkit-side manifest store | Richer metadata but a second bookkeeping surface that can drift. | |
| Hybrid: disk truth + history journal | Tree from files; append-only journal for timestamps/results. | |

**Q2 — Persist-history retention?**

| Option | Description | Selected |
|--------|-------------|----------|
| Session-only (Recommended) | From the in-memory orchestrator log; clears on restart. | ✓ |
| Durable journal file | Survives restarts; more to maintain + drift-proof. | |
| Session + last-result cache | Session history + per-row last-result badges cached to disk. | |

**Q3 — What do the Scene tools drive?**

| Option | Description | Selected |
|--------|-------------|----------|

| Launcher + reload only | Defer bookmarks. | |
| Reload only, defer launcher | Leaves the §4 verify pass unproductized. | |

**Q4 — Which override dir offline?**

| Option | Description | Selected |
|--------|-------------|----------|

| Option | Description | Selected |
