## Accomplishments

### Per-template mirroring PROVEN LIVE, cross-instance — a project first

Edited building `1105879`; building `1106500` — never edited, no `edit_*.ilf`, nothing
session-specific — rendered that edit after `refreshInteriorLayout`, because both resolve to one
`shared_cloning_facility.ilf`. D-08's "all buildings with this layout show the edit" had been a
design claim carried by unit tests for the entire phase. Not a checkpoint step; it fell out of
building step 11's fixtures.

**Corollary worth keeping:** a second instance rendering the UN-edited layout is not evidence that
mirroring is off — it is ordinary staleness. Only a post-`refreshInteriorLayout` observation
distinguishes them, and reading a stale instance as "correctly unmirrored" was done live before the
refresh settled it.

### Shared-mirror edits ACCUMULATE — a silent data-loss risk measured and cleared

If `edit_<id>.ilf` derived from pristine stock rather than the current mirror, two buildings sharing
a mirror path would clobber each other with no warning. Nothing in the phase would have caught it:
until this session no two edited buildings had ever shared a mirror path. Measured against pristine
stock pulled from the TREs — building A's file carries B's edit (region 477-522) plus its own
(2193-2238). Composes, does not replace.

The obvious form of this test proves nothing: both buildings' first edits hit the SAME row, giving
one identical region in both files, which cannot distinguish accumulation from replacement.

### Four reporting defects found and fixed — every refusal was already correct

None was a functional fault. The entire two-session investigation was paid to reporting.

1. **`persistDecorationEdit()`'s refusal reasons were discarded** — returned by the function,
   dropped by its only caller. No capture sent → no result → no Activity entry → nothing on the
   strip → arm left set. Completely silent. Same class as `dda0edd` (placement path, fixed one day
   earlier); the persist path was never re-checked. *Fixed; code-reviewed only, no live repro found.*
2. **`DecoStripState::Failed` was structurally unreachable** — `Armed` is tested first and a failed
   rebind deliberately keeps the arm, so sketch 020-A's `failed` state essentially never rendered
   for persist failures. *Fixed; verified live twice.*
3. **Channel strings decoded as windows-1252** — `TextDecoder('ascii')` is a WHATWG alias for it, so
   the agent's 7 deliberate UTF-8 em-dashes surfaced as `â€"`. *Fixed + regression test; verified live.*
4. **The abort reason never left the Log tab** — the Activity accordion, which D-12 makes the owner
   of decoration outcomes, received only `decorationResultLabel(ABORTED)` = `"aborted"`. *Fixed;
   verified live.*

Also: "nothing is mounted" was reported as `readVfs: no VFS entry ...`, which reads as "that asset is
missing". Now says so plainly.

**These sharpen SC1's intent**, recorded in D-12's annotation: a surface showing *nothing*, or a
true-but-empty word, satisfies "no raw codes" and fails the decision. SC1 is that a failure is
EXPLAINED, not merely worded.

### An inherited hypothesis falsified by measurement

The handoff's Finding-2 candidate fix — "drop the frame-1 `cleanupScene` and let v33 tear down the
outgoing scene" — is **wrong**. Tested live behind one narrow flag: `candidates=0` unchanged. Two
findings from the negative run: `loadScene` with a live scene **no longer FATALs** on v33 (the
condition that forced 05.1-16's two-frame sequence), and the shipping path **leaks the outgoing
`GroundScene`** while the experimental one would not (reasoned, not measured). Flag reverted; report
filed at `.planning/handoff/2026-08-07-TOOLKIT-REPORT-editor-scene-sphere-tree.md`.

## Notes for whoever picks this up next

- **`.ws` full-resave drifts ~2000 scattered bytes and this is NORMAL** — 1-2 ULP quaternion drift,
  proven pre-existing by A/B on last session's own controls. Do not read it as corruption. The defect
  signature remains an **84-byte NODE** appearing, or a size delta that is not exactly
  `strlen(path)+1` per novel template.
- **The `(NEW)` marker lives exactly ONE tree-diff generation** and cannot survive any refresh.
- **Two reusable tools were built and are worth promoting to `packages/harness/scripts/`:** the `.ws`
  node parser (FORM/NODE/DATA framing, OTNL index, field offsets) and `list-interiors.cjs` — a
  building is decoratable iff an `interiorlayout/<portal-layout>.ilf` exists, and only **298** do
  against ~1,178 building templates. Note `.ilf` names follow the PORTAL LAYOUT, not the building
  template, so they cannot be assumed to correspond.
- **There are THREE object classes, not two** (recorded in the exterior-`.ws` todo): interior `.ilf`
  decorations (built), exterior `.ws` nodes (designed, not built), and **server-spawned objects**
  (not designed — the cloning terminal comes from swg-main's `cloning_facility_terminal.tab` and
  needs a datatable edit + server push, not `wsSaveSnapshot`). Class 2 is overwhelmingly the common
  case — Tatooine's snapshot alone holds 15,808 node records.
