## Accomplishments

- **`AddDecorationModal.tsx`** — 021-A Frame 1. Search + thumbnail grid over `useTreStore`'s
  ALREADY-MOUNTED `vfsEntries` (no new asset-discovery service, no disk walk), scoped to the
  decoration-shaped path convention the `.ilf`'s own `objectTemplateName` values use. Presentation
  and selection only: it never calls `sendStartPlacement` and never shows a toast, so all display
  timing stays with the panel (R9/BB1). A selection the current filter no longer matches is
  dropped, so Place can never send a template the user can no longer see.

- **ADD trigger + context (Task 2)** — resolves the target building/cell from the selected row via
  `parseWorldEditorRowId` (the shared discriminator, never a local colon-split): a decoration row
  contributes its exact `cellName`, a building row borrows its first decoration's. D-04's degrade
  is words, never a silent no-op — a zero-decoration building, no selection, or no attached client
  each disable the trigger with the reason stated.

- **The "(NEW)" marker (Task 2)** — a per-building count-map walk keyed on CONTENT identity
  (`buildingId`+`cellName`+`objectTemplateName`), so a pure reindex can never be mislabeled. Keyed
  on the `tree` VALUE rather than history growth (V2), so `prevTreeRef` advances on EVERY
  `refreshTree()`-triggered update and can never go stale between refreshes. A null-sentinel first
  pass and the reversed absent-building rule (V3) keep a fresh mount or a building's first
  observation from mass-marking. Undo's own refresh drains Plan 13's suppress QUEUE and pre-credits
  each restored tuple — absorbing the restore while still marking any OTHER row that lands in the
  same window (X3/Z5). The diff always runs; it is never a blanket skip.

- **The HOST_CMD ACK PROTOCOL consumer (Task 3)** — Plan 08's canonical spec implemented as the
  full 13-row table. No toast at send time; the returned epoch enters a single pending slot
  carrying its issuing `studioDir`, so ack-vs-switch (row 7), timeout-vs-switch (row 9), and
  detach-vs-switch (row 10/EE2) all resolve LOCALLY rather than by effect declaration order.
  Refuse-while-pending is a self-loop that never overwrites the slot (row 13). Refusal, timeout,
  and detach each leave a durable words-only history entry + failure badge.

## Deviations & Corrections

- **A real regression found and fixed at the source.** The new refresh-on-persist effect made every
  Remove pay a SECOND full override-dir scan: `handleRemove` records its history entry and then
  calls `refreshTree()` itself, so the growth-triggered effect fired on top of it. Caught by Plan
  13's own existing assertion (`scanWorldEditorState` called twice, not three times). Fixed by
  having `refreshTree()` stamp the history length it observed, so the effect fires only for growth
  that nothing else rescanned for — i.e. the ADD path, where the poll loop is the only signal.
  Relaxing the existing assertion to 3 would have hidden a redundant disk scan on every Remove.

- **Two of this plan's own new tests were wrong on first run, not the implementation.** Recorded
  because both were assertions that would have passed for the wrong reason:
  1. The row-7 (CC2) test asserted the trigger re-enabled after a project switch — but the switch
     also resets `selectedRowId`, so the button was disabled for lack of a selection. It now
     re-selects a row first, so the assertion is genuinely about the pending lock being cleared.
  2. The V2 mirror-toggle test asserted zero markers after a follow-up refresh whose scan returned
     IDENTICAL content — the tree reference never changed, so the effect never re-ran and the
     assertion proved nothing. It now makes the later refresh add a row in the OTHER building and
     asserts only that row is marked, which is the actual proof that `prevTreeRef` advanced on the
     toggle rather than going stale.

## Carve-outs (documented, not silently passed over)

1. **X8 — the "(NEW)" baseline is component-local.** A mid-flow tab navigation that unmounts and
   remounts the panel during the ADD round trip resets `prevTreeRef`, and V3's null-sentinel
   first-pass rule then silently swallows that ONE in-flight ADD's marking. Disclosed and accepted
   for this phase per the plan; the permanent fix (hoisting the marker + baseline into
   `worldEditorStore`, which would also close Plan 15 ledger item (g)) is deferred. Every OTHER ADD
   still marks its row.
2. **C6 — the eligible-building set is narrower than RESEARCH.md recommended.** ADD is available
   only for buildings already visible in the World panel's tree (previously-edited, ≥1 decoration).
   A never-edited stock building is not selectable even when its stock `.ilf` could supply a
   borrowable cellName, because D-05's disk scan never surfaces it.
3. **C6 residual — same-building wrong-ROOM placement is possible.** Plan 12's building-id guard
   closes the wrong-BUILDING case; nothing verifies the click landed in the correct room of a
   multi-cell building. Mitigated informationally only: the success toast warns to click only in
   the same room as the selected decoration.
4. **The grid is capped at 200 tiles.** Self-disclosing in the footer with the true match count.
