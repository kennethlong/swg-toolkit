# Phase 05.1 Plan 13: World-panel Remove/Undo (D-02/D-03) Summary

**Per-row decoration Remove, guarded by a sticky-error-aware 8-second undo toast — always a durable data-only `.ilf` removal via the same byte-exact model-D path as an edit/add, with the live-despawn branch honestly documented as unit-proven but unreachable this phase (C4).**

## Accomplishments

- `removeUndoStore.ts` (new): sibling to `deleteUndoStore.ts`, scoped to decoration rows —
  `pending: RemovedRowEntry[]` + `push`/`restore`, a per-entry-keyed `undoErrors: Map<id, message>`
  (`setUndoError`/`clearUndoError` never touch a different id's slot — the cross-entry-erasure
  regression this plan closes), and `reset()` registered via a module-scope `workspaceStore`
  subscription identical in shape to `worldEditorStore.ts`'s own PROJECT-SWITCH RESET ORDERING
  CONTRACT (reset-before-render, synchronous).
- `decorationPersistOrchestrator.ts` gains `removeDecorationRow` (fails closed with a words-only
  message when `buildingTemplateVfsPath` is unknown; the optional `sendDespawnNode` branch is
  implemented, unit-tested with a directly-passed non-null id/mappingName pair, and best-effort
  — a despawn failure never blocks the already-committed data removal) and
  `addBackDecorationRow` (Undo's re-add, via the SAME `assembleDecorationEdit({kind:'add'})` path
  — append-only, so a restored row lands at the end of its cell, an accepted, disclosed
  consequence per ROUND-3-REVIEW R7).
- `RemoveUndoToast.tsx` (new): purely presentational — a required `onUndo` prop is its ONLY
  write-adjacent surface; it never calls `restore()` or any add-back helper itself. Implements
  the sticky-error guard (a failed Undo's error display holds until dismissed or successfully
  retried, and is never silently folded away by an unrelated new removal arriving mid-freeze),
  the ROUND 9 no-timer-while-sticky fix, and the ROUND 10 mount-time reconstruction (a mid-session
  remount restores an already-sticky display and its frozen freeze-baseline instead of losing it).
- `WorldPanel.tsx`: every decoration row gains a "×" Remove action (no confirm dialog) that
  resolves `overrideDir`/`readVfs`/`studioDir` via the SAME `resolveOverridePair()` every other
  write action in this file already uses, always passes `liveNetworkId: null` (C4 — no producer
  in this phase populates one), pushes a `RemovedRowEntry`, records a `formatPersistMessage`
  "warn" history entry (D-10's mirror-off suffix applies to Remove too), and refreshes the tree.
  `handleUndo` owns the FULL restore: resolve building + a fresh override pair -> add-back write
  BEFORE `restore()` pops the entry (so a thrown add-back can never present a false "restored")
  -> `clearUndoError` -> push the restored row's identity onto `suppressNextDiffRef` (a queue,
  groundwork for a later plan's consumer, never exercised here) -> `refreshTree()`.

## Decisions Made

- `removeDecorationRow`/`addBackDecorationRow` both call the file's existing `stageDurable` helper
  (the same one `handleDecorationCapture` uses) so a Remove/Undo's staged entries land in
  `stagingStore` the same way a live persist's do — the plan's `read_first` note explicitly names
  `stageDurable` as reused by this new function, so this is a spec-completion, not scope creep.
- `addBackDecorationRow` also fails closed on an empty `buildingTemplateVfsPath`, mirroring
  `removeDecorationRow`'s own guard, even though the plan's text names this check only for Remove
  — defensive symmetry (Rule 2: missing critical functionality), since a building's stock
  template path could theoretically become unknown between a Remove and its Undo.
- Implemented `RemoveUndoToast`'s sticky-error guard, mount-time reconstruction, and no-clear-at-
  top ordering directly against the plan's FINAL (ROUND 10/R9) specification — the plan document
  itself records nine rounds of revision to this mechanism; this executor built the end state
  once rather than any intermediate shape.
- The per-row Remove button is a plain `×` icon button (aria-label `Remove {template basename}`,
  `data-testid="world-remove-decoration-btn"`) rather than a text button, matching this panel's
  existing compact-row idiom (badges, small icon glyphs) — no sketch element specifies its exact
  visual form (see Sketch diff below).
