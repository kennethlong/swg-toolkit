## Accomplishments

- `worldEditorScan.ts`: `scanWorldEditorState(overrideDir, buildingTemplates?)` lists every `interiorlayout/toolkit/edit_<id>.ilf`, pairs it with `object/building/toolkit/edit_<id>.iff`, derives a human display label from the derived template's own `DERV`/base chunk (real shape verified against `shared_cantina_tatooine.iff` this session — `FORM SBOT -> FORM DERV -> leaf XXXX` = the base template's asciiz path), and enumerates decoration rows with `rowIndex` recomputed fresh every scan (never cached).
- `buildingTemplateVfsPath` (ROUND 3, R3): read from the caller-supplied durable `buildingTemplates` map, keyed by the raw `<id>` filename suffix — empty string, never `undefined`, when the map has no entry.
- `resolveScanRoot(clientExe, offlineBinding)`: live-attached path mirrors `decorationPersistOrchestrator.ts`'s `resolveRunningClientOverrideDir` (detectClients + longest-installPath-prefix match); offline path calls `resolveOverrideDir` directly against the caller-resolved `{ cfgPath, clientPath }` pair; guards the undefined-`cfgPath` case (ROUND-3-REVIEW R9) without ever calling `resolveOverrideDir` with an unchecked optional.
- `worldEditorStore.ts`: `useWorldEditorStore` holds `tree`/`selectedRowId`/`sessionOverlay`/`history`/`hasFailureBadge`/`lastHostCommandResult`. `refresh()` reconciles `sessionOverlay`/`selectedRowId` against a freshly-scanned tree by content identity (never stale `rowIndex`), verified directly against both the "shifted index, same content" case and the "content genuinely removed, freed index reused by something else" case (ROUND-3-REVIEW R3).
- `recordArmFailure(reason)` (C8) closes the cross-AI review's dead-end: an agent-side arm failure now has a real, tested landing spot in the same history/badge machinery `recordPersistResult` uses (shared `pushHistoryEntry` helper — no duplicated badge logic).
- `worldEditorRowId`/`worldEditorBuildingRowId`/`parseWorldEditorRowId` (ROUND 3, R12/MED-7) give every later plan (10/13/14) one shared row-id contract instead of ad-hoc parsing.
- `formatPersistMessage(baseLabel, mirrorToStockIlf)` (D-10) is the single App-side implementation of the mirror-off hybrid-session warning suffix, exact string verified.
- `reset()` restores all six fields and is invoked SOLELY by a module-scope synchronous `useWorkspaceStore.subscribe()` registered at the bottom of `worldEditorStore.ts` — the PROJECT-SWITCH RESET ORDERING CONTRACT (reset-before-render, R9 review BB2/BB5), never a React effect. Verified synchronously with no component mounted (P2 registration-at-import gate), plus the initial `null->project` open does NOT reset while a `project->project`/`project->null` transition DOES. HMR dispose block + test-isolation recipe comment included per R10 review CC9.
- `lastHostCommandResult`/`setLastHostCommandResult(epoch, code)` (ROUND 10, AA4) — the HOST_CMD ack-correlation landing field for Plan 08 (writer) and Plan 14 (reader); each call proven to replace with a NEW object (reference inequality), never mutate in place.

## Decisions Made

- Building display label derivation reads the derived template's own `FORM SBOT -> FORM DERV -> leaf XXXX` (base `.iff` path), basename-without-extension, `shared_` prefix stripped — verified against the real `shared_cantina_tatooine.iff` fixture on disk this session (base = `object/building/base/shared_base_cantina.iff` -> label `base_cantina`), not fabricated from the docs tree.
- `recordPersistResult(entry: PersistHistoryEntry, rowId?: string)` — added an optional second parameter not spelled out verbatim in the plan's action text, because the plan's "updates sessionOverlay for the affected row" behavior is otherwise unimplementable: `PersistHistoryEntry` carries `buildingLabel`/`decorationLabel` (display strings) and only *optional* `cellName`/`rowIndex`, never a `buildingId`, so there is no way to derive a `worldEditorRowId` from the entry alone. The optional `rowId` lets a caller that HAS already resolved the row (Plan 08's RESULT-time wiring, Plan 13/14) pass it through; omitting it (as this plan's own tests mostly do) skips the overlay update, matching every acceptance criterion in this plan (none of which requires `recordPersistResult`'s sessionOverlay side effect — only `hasFailureBadge` and history accumulation are tested at this plan's level).
- The P1 standing gate's search needle is built at runtime via `['flush','Sync'].join('')` inside the test, and the test excludes its own file from the directory walk — a raw literal occurrence of the identifier in either the store's comment or the test's own source would otherwise trip the gate against itself (the CC15 self-clean rule, taken literally and verified: an earlier draft that spelled the identifier out in a comment DID fail its own gate on the first run).
