## Accomplishments

- **Task 1 (panel registration):** `world` added to WorkspaceShell.tsx's `panelComponents`/`STATIC_PANEL_IDS`/`PANEL_TITLES`/`PANEL_REOPEN_POSITIONS`, docked `{ direction: 'within', referencePanel: 'inspector' }` alongside Inspect/Deploy/VCS per 019-A's tabstrip. `workspace-config.ts`'s `LAYOUT_VERSION` bumped 4→5 (a returning user's saved layout is discarded and rebuilt with the World tab present) plus an `addPanel({ id: 'world', ... })` call in `buildInitialLayout` immediately after `vcs`.
- **Task 2 (panel body):** `WorldPanel.tsx` renders 019-A's building-first tree — buildings own the hierarchy (icon, `displayLabel`, `derivedTemplatePath` basename + node id, an aggregate status badge), decorations nest indented under their building (icon, `objectTemplateName` basename, `cellName · row N`, a per-row badge) — using `worldEditorBuildingRowId`/`worldEditorRowId`/`parseWorldEditorRowId` for every row id (never ad-hoc string construction).
- `resolveOverridePair()` is the ONE shared, null-safe helper (co-located with `refreshTree()`) every read/write call site in this file uses: it reads `studioDir` via `useWorkspaceStore.getState()` (never the hook-selector form — this function runs from event handlers, where a hook call would throw "Invalid hook call"), guards `!studioDir` before ever calling `readWorkspaceJson`, resolves `overrideDir` via `resolveScanRoot`, and returns `null` immediately on either guard failing — never constructing a `readVfs` or letting a `string | null` flow into a `string`-typed dependency.
- `refreshTree()` calls `resolveOverridePair()` and either renders the words-only "no live session / project not bound to a client" disabled state (never calling `refresh()`) or calls `refresh(pair.overrideDir, pair.meta.worldEditorBuildingTemplates)` with a FRESHLY re-read `meta` every time. It is the ONE call site the mount effect (re-running on `liveStatus.kind` change), the live-strip's refresh button, and the mirror toggle's `onChange` all share — never a stale mount-time value anywhere in this file.
- The mirror toggle's `onChange` resolves via `resolveOverridePair()` and calls ONLY `reconcileMirrorMode(pair.studioDir, pair.overrideDir, pair.readVfs, nextValue)` — this panel never calls `updateWorkspaceMeta` directly (`reconcileMirrorMode` is the sole persistence owner, closing D-09's two-writers risk). A non-empty `failures` result records a durable `worldEditorStore.history` entry (`outcome: 'error'`): the unconditional "no buildings' mirrors were changed" wording when every entry carries `diskState: 'unchanged'`, and the ROUND 5/V7 hedged wording naming the specific `'uncertain'` building id(s) when any entry doesn't. `refreshTree()` runs at the end regardless of outcome, so the switch's rendered state always reflects what actually landed on disk/settings (reverting to the pre-toggle value on any failure, since a blocked/rolled-back reconcile never persists).
- D-08's locked scope control renders BOTH the active Per-template switch AND a visible, `aria-disabled="true"` "Per-instance (server repoint)" option with its "coming later" hint — not omitted (an earlier draft mislabeled this "Claude's discretion to omit"; this plan corrects that).
- The selection detail card shows Decoration/Cell·row/Position/Last persist/Files. "Last persist" renders D-13's FULL 12-element before/after transform readout (grouped 4-per-row, 2 decimals) when the matching history entry carries it — proven to render visibly-different text on a rotate-only edit (same translation, different rotation) by a dedicated regression test — falling back to the outcome-word-only message when the entry lacks transform data, and to "not yet persisted this session" when no matching entry exists at all. The inert "Go to"/"Revert"/"Edit in game" stub buttons show the honest `"{label}: not yet wired — coming in a later phase."` via `log()`, never the sketch mock's success-implying copy.
- D-12's failure badge is REAL: one effect calls `props.api?.setTitle('World' + (hasFailureBadge ? ' ●' : ''))`; a second effect subscribes to `props.api.onDidActiveChange` AND checks `props.api.isActive` synchronously once on mount (covering the case where the tab is already active when it mounts, since the change event only fires on a transition) — both call `acknowledgeFailures()` on activation, never on mount alone.
- The live-session strip subscribes to `useLiveStore` via two SEPARATE selectors (`status`, `clientLabel` — never `liveStatus.clientLabel`, which does not type-check) and shows a D-07b mismatch hint when the attached client's exe path doesn't match the project's bound client path (informational only, never blocking).

### Documented discretion / disclosed gaps (not defects — explicitly called out per this plan's own instructions to surface sketch-vs-plan conflicts rather than silently resolve them)

**1. [Sketch-vs-reality gap] The live-strip's "scene chip" has no backing data source anywhere in this codebase.**
- 019-A's mock shows a scene chip (e.g. "tatooine"). Checked `liveStore.ts`, the shared channel contracts (`@swg/contracts`), `worldEditorStore.ts`, and Plan 11's own PLAN.md (the Scene accordion) — none of them track the attached client's current scene/planet name. This is a genuine capability gap, not an omission of this plan's own scope.
- **Resolution:** the live strip renders an honest `scene: not tracked yet` placeholder (with a title tooltip) instead of a fabricated value. Documented in the file's own header comment for the next plan/session that touches this file.

**2. [Plan-text vs. sketch wording] Building row subtext uses `derivedTemplatePath`'s basename (`edit_<id>.iff`), not the sketch mock's stock-template name (`shared_cantina_tatooine.iff`).**
- The plan's Task 2 action text explicitly specifies "`derivedTemplatePath`'s basename + `· node {buildingId}`" for this subtext — followed verbatim. The 019-A sketch mock's example text shows the STOCK building's filename instead. Per this plan's own instruction to state sketch/plan disagreements explicitly: the plan's literal instruction was followed over the sketch's mock text, since the plan's own words are the operative spec for this element.

**3. [Claude's discretion, documented in-code] Badge derivation does not implement the sketch's "N UNAPPLIED" state.**
- The disk-scanned tree (D-05) carries no field distinguishing "confirmed applied this session" from "always was on disk" — there is no reliable signal to derive an UNAPPLIED count from in this plan's data model. `deriveBuildingBadge`/`deriveDecorationBadge` (documented in `WorldPanel.tsx`) use FAILED > ARMED > SAVED precedence instead, where SAVED is the default for anything not armed/failed this session (consistent with D-05: anything in the tree is, by definition, persisted).

**4. [Testing gap, not a stub] The "Files" field's `hasMirror` best-effort check has no positive-path test.**
- All 20 tests exercise `hasMirror`'s negative path (mocked `readVfs` returns a stub buffer that `readInteriorLayoutFileName` can't parse, so it resolves `false`) — no test seeds a real mirror file on disk to assert the `· mirror` suffix actually appends. The code path is real (not a stub) and wrapped in try/catch so it can never throw; only its positive branch lacks direct test coverage.

**5. [Acceptance-criteria interpretation] "the tabstrip renders 'World'" is verified at the WorkspaceShell/workspace-config level (Task 1), not inside `WorldPanel.test.tsx`.**
- Dockview's own tab chrome renders the panel's `title` (set via `PANEL_TITLES.world = 'World'` and `addPanel({ title: 'World' })`); a standalone RTL render of `WorldPanel` (this component's own body only) never mounts a real `DockviewReact` tabstrip, so there is nothing for a `WorldPanel`-scoped test to assert about a tabstrip. `WorkspaceShell.test.ts`/`workspace-config.test.ts` (unchanged by this plan, still green) already cover the `world`/`'World'` title registration this acceptance line is really about.
