## ⚑ CONSENSUS — ranked by cross-reviewer convergence (the `--reviews` replan work-list)

### C1 — [BLOCKER] Channel size bump 1308→1864 is unowned on the host + agent side
**Reviewers: Codex, Cursor, Opus, Fable (4/5, source-confirmed).**
Plan 03 grows `LiveState` (in `channel.h` / `contracts/live-inject.ts`) to 1864 bytes but its
`files_modified` omits the two files that hard-code the size:
- `packages/live-inject/agent/channel.cpp:25` — `static_assert(sizeof(LiveState) == 1308)` → **agent DLL
  fails to compile at the first Wave-1 `cmake` build (Plan 05)**, an error in a file Plan 05 doesn't own.
  No plan adds `offsetof` guards for the 11 new fields — the compile-time cross-language guard is dropped
  precisely for the new, hand-diffed region.
- `packages/live-inject/src/channel_binding.cpp:58` — `CHANNEL_BYTE_SIZE = 1308` governs the mapping,
  the `ArrayBuffer::New`, and `readChannelView`'s whole-view copy. If never bumped, `readChannelView`
  returns a 1308-byte buffer and Plan 08's `parseHostCommandResult` (offsets 1856/1860) throws a DataView
  RangeError **every poll tick in the real app — taking down the proven decoration pipeline too** — while
  Plan 08's synthetic-1864-buffer tests stay green. Windows page-granularity (4KB) makes the C++ writes at
  1440+ silently *work*, so the failure presents as JS-only and maximally confusing.

**Fix:** add `channel.cpp` + `channel_binding.cpp` to Plan 03's `files_modified`; bump both size touchpoints
(ideally one shared constant); add `offsetof` asserts for the new fields; change Plan 03's verify from
contracts-TS-only to **contracts build + agent cmake build + host addon build all green**.

### C2 — [BLOCKER] The ADD `kind`/`cellName` encode + decode is read by 3 plans, wired by 0 → ADD silently becomes EDIT
**Reviewers: Cursor (2 findings), Opus, Fable (3/5, source-confirmed).**
- **Decode:** `packages/renderer/src/services/decorationChannel.ts:36-61` `parseDecorationCapture()` reads
  only the original six fields. Plan 03 adds `kind?`/`cellName?` to the TS interface only; no plan updates
  the decoder (Plan 01 touches the file only for the REBIND_REFUSED label). `capture.kind` is `undefined`
  forever.
- **Encode:** `packages/live-inject/agent/channel.cpp:178-200` `channelWriteCapture()` writes from the
  plain `DecorationCapture` struct (`channel.h:149-155`), which Plan 03 explicitly does NOT extend. Plan 12
  (`files_modified: overlay.cpp` only) cannot touch `channel.cpp`/`channel.h`, so nothing writes offsets
  1308/1312 under the capture seqlock.
- **Consumers:** Plan 06 (`kind: capture.kind === 'add' ? …`), Plan 08 Task 3, Plan 12 all *read* the
  fields. Because `kind` is always `undefined`, **every ADD assembles through the edit path →
  `resolveNode` on a freshly-placed node → "could not resolve" → ADD persist fails. SC4 broken.** Masked by
  unit tests that hand-build the capture object with `kind` pre-set.

**Fix:** assign explicit tasks — (a) extend `parseDecorationCapture` to read 1308/1312 inside the
seq1…seq2 window + a `decorationChannel.test.ts` ADD-kind case; (b) extend the plain `DecorationCapture`
struct + `channelWriteCapture` to write kind/cellName between seq increments; (c) one integration test that
drives a real ADD-kind buffer through parse→orchestrator, not a mocked capture.

### C3 — [HIGH] `studioDir` never threaded into the live persist ctx → mirror resolves to default-ON forever
**Reviewers: Fable (root cause); reinforces Opus M4 + Codex mirror-off.**
`useChannelReader.ts:270` calls `handleDecorationCapture(cap.epoch, cap.capture, { mappingName, clientExe })`.
Plan 06 adds `studioDir` to the ctx but Plan 06's `files_modified` is orchestrator-only and Plan 08 (which
owns `useChannelReader.ts`) never threads it in. If optional, everything compiles and unit tests pass
(they inject `studioDir`), but the **live** persist resolves `mirrorToStockIlf` to the default `true`
forever → mirror-OFF reconcile removes mirrors, next persist re-creates them (**the exact D-09 stale-mirror
failure this phase exists to close**), and `writeRebind` never carries `MIRROR_OFF` so D-10's "saved (not
visible here)" strip variant never fires live.

**Fix:** thread `useWorkspaceStore.getState().studioDir` into the ctx as an explicit behavior bullet + test
in Plan 08 Task 3 (already editing that block).

### C4 — [HIGH] Remove's live-despawn depends on a live node id that never reaches the renderer → dead code
**Reviewers: Codex, Sonnet, Cursor (3/5).**
Plan 13's conditional live-despawn keys off a `liveNetworkId`/WS node id per row, but no plan populates it:
Plan 04's `sessionOverlay` is only `armed|saved|failed`, and Plan 12's placement flow despawns its own temp
`wsAddObject` node right after a successful persist — so by the time Remove could act, no row carries a live
id. The "opportunistic live despawn" branch is dead as delivered.
**Fix:** either expose the spawned WS node id to the renderer via CAPTURE/RESULT into a named
`sessionOverlay` field (Plan 12 hook) and defer its auto-cleanup, or relabel Plan 13's branch aspirational
and drop the live-despawn promise for rows.

### C5 — [HIGH] Real-`.ilf` byte-exact round-trip is optional, not mandatory (project's #1 mandate)
**Reviewers: Codex, Cursor, Opus (3/5).**
Plan 01 Task 4 registers `.ilf` in the CORE-05 gate against a hand-built **byte-recipe** fixture; the
real-asset lane "SKIPs cleanly when absent" and Task 5's checkpoint permits closing with "real-asset round-
trip still owed." A format-mutating change (row append/delete) can therefore ship green having never round-
tripped a real client `.ilf`. AGENTS.md's #1 constraint ("actual asset bytes before implementing any
parser/serializer") argues the real-asset lane should be **mandatory** for append/delete, reusing the real
`.ilf` the proven edit pipeline already validated against.
**Fix:** make the real-`.ilf` `addNode`/`removeNode` round-trip a required assertion (not skip-on-absent);
keep the recipe fixture as a supplement. Align Plan 15 sign-off with Plan 01 Task 5's outcome (fail, not
merely "record," if real-byte proof is missing).

### C6 — [HIGH] cell-name degrade can write the WRONG cell / is narrower than the decided degrade
**Reviewers: Codex (wrong cell), Sonnet (multi-cell), Fable (stock-building gap) (3/5, different facets).**
- Codex: borrowing a `cellName` from the selected row only works if placement is constrained to that cell;
  the overlay ghost/click flow does not enforce it — select a row in `alcove1`, click in another room, and
  you append an `.ilf` row with the wrong `cellName`.
- Fable: the borrow source is `worldEditorStore.tree`, which per D-05 scans only the override dir
  (`edit_*.ilf`). A never-edited stock building isn't in the tree → Add stays disabled. The shipped
  constraint is "ADD only into a building you've already *edited*," not RESEARCH's "cell already has ≥1
  decoration" (the stock `.ilf`, readable offline via VFS, could supply the cellName).

**Fix:** constrain placement to the selected cell (or fail placement outside it), AND implement the stock-
`.ilf` fallback cellName lookup — or surface the narrower constraint to the maintainer as an explicit
scoping decision before execution, not at the Plan 15 demo.

### C7 — [MEDIUM] D-10 mirror-off state resolved twice → the two surfaces can disagree for one persist
**Reviewers: Codex, Opus (2/5).**
The strip's "saved (not visible here)" is driven by the `MIRROR_OFF` bit set at **write** time (Plan 06);
the App history line is built at **RESULT** time by re-reading `readWorkspaceJson().mirrorToStockIlf`
independently (Plan 08 Task 3). Flip the toggle between write and result and the two surfaces describe
opposite mirror states for the same persist — contradicting D-10, which Plan 15 step 9 verifies *together*.
**Fix:** carry the resolved mirror-off boolean through the `pendingCapture` correlation and format from it,
not from a re-read at RESULT time.
