## ⚑ ROUND-4 WORK-LIST — ranked by severity and by "new seam the fix opened"

### W1 — [HIGH] `reconcileMirrorMode` is atomic on the FLAG but not on DISK → a partial reconcile moves the successful buildings' mirrors while the flag stays unpersisted (D-09 stale-override, one layer down)
**Sonnet HIGH (new — opened by R6 itself).** R6 correctly gated `updateWorkspaceMeta({ mirrorToStockIlf })` on
`failures.length === 0`. But `reconcileMirrorMode`'s per-building loop *continues past* failures (`does not
throw, do not abort the pass`) and, for every building NOT in `failures`, it has already written/deleted that
building's stock mirror to match `nextValue`. So on a mixed pass (building A known → mirror deleted; building B
unknown → pushed to `failures`), the persisted flag stays `true` (never updated), but A's mirror is already gone
on disk. Disk and flag now disagree for exactly the buildings that succeeded — the next persist to a new
building C reads the still-`true` flag and writes C's mirror while A sits mirror-less. This is precisely the
stale-override class D-09/R6 exist to close, reopened at the disk layer: R6 made the *global flag* atomic, but
the *cross-building reconcile* is not. Plan 10's switch-revert + durable history entry correctly reflect that
the flag didn't move, but cannot know disk moved anyway. Not exercised by Plan 15's sign-off (no mixed
known/unknown toggle-flip step).
**Fix (design pick):** either make `reconcileMirrorMode` transactional (buffer all writes/deletes, commit only
when `failures.length === 0`, matching what R6 already promises for the flag), OR — cheaper — on any failure,
restore the successful buildings' mirror state back to the pre-toggle value so "flag didn't move" and "disk
didn't move" stay true together. → **Plan 06** (+ **Plan 15** sign-off: add a mixed known/unknown-building
toggle-flip step).

### W2 — [HIGH] Undo's re-add never calls `refreshTree()` → the tree goes stale AND Plan 14's positional "(NEW)" diff later mislabels the restored (reindexed) row as a fresh placement
**Sonnet HIGH (new — R2's refresh discipline reached Remove but not Undo).** Plan 13 Task 2's Undo path calls
`restore(id)` + the add-back helper and shows a toast, but has **no** `refreshTree()` call — while Plan 13's own
R2 requirement is that *every* disk mutation in this file re-reads state fresh (applied to Remove, missed on
Undo). Because `addNode` is append-only (D-01/R7's disclosed reorder), an undone middle row lands at the END of
its cell on disk; with no `refreshTree()`, `worldEditorStore.tree` and Plan 14's local "(NEW)" snapshot both stay
frozen until some *unrelated* later event triggers a refresh. Plan 14's "(NEW)" marker is a positional
`worldEditorRowId` diff (not content identity), so when that later refresh lands it sees the restored row at a
new index and tags it "(NEW)" — misrepresenting a restore as a new add. Duplicate-template cells make the
resulting mislabel harder for the user to disambiguate, but the root cause is the missing refresh, not the key.
Plan 15 step 6 only exercises a plain isolated Add, so this survives to sign-off.
**Fix:** Plan 13's Undo handler calls the shared `refreshTree()` immediately after the add-back completes (same
helper Remove already uses). Independently, Plan 14 keys its "(NEW)" diff on the SAME content-identity resolution
Plan 04 already built for `sessionOverlay`, not a raw positional-id Set, so a reindex from any cause can't be
misread as new. → **Plans 13, 14** (+ **Plan 15** sign-off: add a Remove→Undo→refresh step).

### W3 — [MEDIUM] R8/M3's `overrideDir === null` guard reached `refreshTree()` but NOT the mirror-toggle (Plan 10) or Remove (Plan 13) call sites → `string | null` flows into `string` params (`makeReadVfs` / `reconcileMirrorMode` / `removeDecorationRow`) = real `tsc` error
**Cursor MEDIUM (the half-propagation class again, smaller).** `refreshTree()` has the guard (`if (overrideDir
=== null) … do NOT call refresh()`, Plan 10). But Plan 10's mirror-toggle `onChange` resolves `overrideDir` then
calls `makeReadVfs(overrideDir)` + `reconcileMirrorMode(studioDir, overrideDir, …)` with no early return, and
Plan 13's Remove click handler calls `makeReadVfs`/`removeDecorationRow(…, overrideDir, …)` with no specified
null branch. `resolveScanRoot(): string | null` feeds `string`-typed params at both sites → would fail
`tsc --noEmit`. (The four consumers: `refresh` guarded ✓; `makeReadVfs`, `reconcileMirrorMode`,
`removeDecorationRow` unguarded ✗.)
**Fix:** extract a shared `resolveOverridePair(): { overrideDir: string; readVfs } | null` carrying the same
guard as `refreshTree()` step 3, and use it from the mirror toggle, Remove, and refresh; or duplicate the
`if (overrideDir === null) return/disable` before every `makeReadVfs` / `reconcileMirrorMode` /
`removeDecorationRow`. → **Plans 10, 13**.

## Consensus summary

- **Verdict:** NOT CONVERGED — but the round-3 dominant seam is CLOSED and no fabrications were injected.
  2 HIGH remain, both single-reviewer (Sonnet, lateral) and both genuinely new.
- **Convergence-from-divergence signal:** this round the reviewers did NOT pile onto one seam — the call-graph
  (Codex), spec/graph (Opus), and factual (Fable) axes all came back clean or near-clean on the R1–R13 fixes,

  HIGHs is a *healthy* signal, not a contradictory one.
- **The two HIGHs are opened by the round-3 fixes themselves:** W1 by R6 (atomic flag, non-atomic disk), W2 by
  R2 (refresh discipline applied to Remove, missed on Undo) crossed with round-3's new Plan-14 "(NEW)" marker.

  half (content-identity keying for "(NEW)"). W3 is a mechanical shared-guard extraction. W4/W5 are prose/cite.
- **Recommended fix approach:** W1 = Plan 06 transactional buffer (cleanest — matches R6's flag guarantee) +
  Plan 15 mixed-toggle step; W2 = Plan 13 Undo→refreshTree() + Plan 14 content-identity "(NEW)" + Plan 15
  Remove→Undo step; W3 = shared `resolveOverridePair()` guard in Plans 10/13; W4/W5 = targeted prose/cite edits.
  All targeted; no re-architecture.
