# Phase 05.1 Plan 06: Per-Project Mirror-Mode + Transactional reconcileMirrorMode Summary

**Removed the hard-coded `mirrorToStockIlf: true` literal from `decorationPersistOrchestrator.ts`, replacing it with a per-project read from `WorkspaceBindingMeta.mirrorToStockIlf`, and added `reconcileMirrorMode()` — a two-phase, transactional (validate-then-apply-with-rollback) reconcile-on-flip that closes the D-09 stale-mirror failure class at the disk level, not just the persisted-flag level.**

## Accomplishments

- `decorationPersistOrchestrator.ts`'s `handleDecorationCapture` now resolves `mirrorToStockIlf` once per capture from `readWorkspaceJson(ctx.studioDir).mirrorToStockIlf ?? true` (default `true`, matching today's behavior for a project-less session or an unset explicit override), replacing the literal `mirrorToStockIlf: true` RESEARCH.md flagged as the wiring point.
- `ctx.studioDir` is optional (`studioDir?: string | null`) so this plan's own `tsc --noEmit` gate stays green at the Wave-1 boundary — the real caller (`useChannelReader.ts`) isn't updated to populate it until Plan 08. Confirmed: `handleDecorationCapture` called with a `ctx` object that omits `studioDir` entirely behaves identically to an explicit `null`.
- `handleDecorationCapture`'s return type widened from `void` to `{ mirrorToStockIlf: boolean; cellName?: string; rowIndex?: number }` (C7/R5). The `mirrorToStockIlf` value is resolved once, before the try/catch, and returned unconditionally on every exit path — success, the `arm-failed` short-circuit, and a caught `assembleDecorationEdit` throw all return the SAME resolved value, proven by a test that forces both a success and a throw against the same project setting and asserts identical returned values.
- A new first branch handles `capture.kind === 'arm-failed'` (C8): calls `useWorldEditorStore.getState().recordArmFailure(capture.cellName ?? '(unknown arm failure)')` and returns `{ mirrorToStockIlf: true }` immediately — no override-dir resolution, no `assembleDecorationEdit` call, no `addon.writeRebind` call at all.
- `capture.kind === 'add'` now threads `kind: 'add'` and `cellName: capture.cellName` through to `assembleDecorationEdit`; every other kind (including omitted/`'edit'`) drops `cellName` unconditionally to `undefined` (ROUND 3/MED-10) — proven with a stray non-empty `cellName` on an edit capture that still resolves via `resolveNode`, not a stale pinned lookup.
- A successful edit/add capture with a bound `studioDir` and a non-empty `capture.buildingTemplateVfsPath` durably merges `{ [sanitizeId(buildingInstanceId)]: buildingTemplateVfsPath }` into `WorkspaceBindingMeta.worldEditorBuildingTemplates` (ROUND 3/R3), preserving pre-existing entries for other buildings; wrapped in its own try/catch so a bookkeeping-persist failure never fails the already-succeeded capture.
- `addon.writeRebind`'s flags argument is now `F.APPLY | (mirrorToStockIlf ? 0 : F.MIRROR_OFF)` (D-10), using the SAME resolved value the return value carries — no second resolution.
- `makeReadVfs` is now exported (ROUND 3/R4) for Plan 10/13.
- `decorationPersist.ts`'s stock-mirror write block is extracted into exported `writeStockMirror`/`removeStockMirror` helpers (C10) — a pure refactor-for-reuse; the existing `decorationPersist.test.ts` suite stays 100% green, proving zero behavior change to the proven edit path.
- New `reconcileMirrorMode(studioDir, overrideDir, readVfs, nextValue): { failures: { buildingId; error; diskState }[] }` (D-09): **Phase 1** validates every building `scanWorldEditorState` (TWO-arg form, reusing the durable `worldEditorBuildingTemplates` map — ROUND-3-REVIEW R1) returns has a known `buildingTemplateVfsPath`, with zero disk writes; any unknown path blocks the WHOLE pass — proven with a two-building fixture where the KNOWN building's mirror is never written despite its path being resolvable (ROUND 4/W1's literal fix target). **Phase 2** resolves each validated building's stock mirror path and groups by that RESOLVED PATH (not `buildingId`) so two buildings sharing a template's mirror file are written/deleted/rolled-back exactly once (ROUND 5/V4) — proven with a shared-mirror-path fixture whose rollback restores the file's actual pre-call bytes (read before unlink, never re-derived from either building's `editedIlfBytes`) with exactly one delete + one restore-write syscall pair. A mid-pass throw on any group STOPS further processing and rolls back every already-applied group via its inverse operation (best-effort — a rollback that itself throws does not block rolling back the rest); every failure carries `diskState: 'unchanged'` except a double-faulted rollback, which carries `diskState: 'uncertain'` (ROUND 5/V7, the disclosed T-05.1-06d residual) — proven with a forced double-fault fixture. The persisted `mirrorToStockIlf` flag only moves via `updateWorkspaceMeta` when BOTH phases complete with zero throws (ROUND-3-REVIEW R6). An unresolvable building's Phase-1 error names the cheap unblock (delete its orphaned `edit_<id>.ilf`) alongside the arm/persist-it-live remedy (ROUND 5/V8).

## Issues Encountered

- Initial test-fixture design used a pre-existing directory at a mirror target path to force a real `fs` throw without mocking. This works for the DELETE direction (`fs.readFileSync`/`fs.unlinkSync` on a directory throw `EISDIR`/`EPERM` on Windows, confirmed via a direct probe) but NOT the WRITE direction — `reconcileMirrorMode`'s own `exists` check treats a directory as "already present," so the `nextValue === true && !exists` branch is skipped entirely and no write is even attempted (no throw). Fixed by switching the WRITE-direction throw-forcing tests (ROUND 4/W1, ROUND 5/V7's write-side) to `vi.spyOn(fs, 'writeFileSync')` with a path-conditional `mockImplementation` that throws only for the targeted mirror path and calls through to the real implementation otherwise.
- A related mistake in the ROUND 5/V4 test: reading `unlinkSpy.mock.calls`/`writeSpy.mock.calls` AFTER calling `mockRestore()` returned empty arrays — `mockRestore()` also clears recorded call history (same as `mockReset()`/`mockClear()`), not just restoring the original implementation. Fixed by capturing the filtered call arrays before calling `mockRestore()`.
