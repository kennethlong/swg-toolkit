## 2. The E2E proof asset — space terminal retexture (success criterion #4)

Verified chain (`shared_terminal_space.iff` → texture). Asset names are **base-retail, identical
across SWGEmu / Infinity / SWGSource** (only the serving archive differs):

```
object/tangible/terminal/shared_terminal_space.iff   (STOT; appearanceFilename ↓)
  └ appearance/ksk_all_spaceterminal.apt
      └ appearance/lod/ksk_all_spaceterminal.lod      (DTLA, 4 LODs)
          └ appearance/mesh/ksk_all_spaceterminal_l0..l3.msh
              └ shaders ↓
```
Shader → texture bindings (verified by parsing each `.sht`):
- body: `shader/…_asb14.sht`, `_asc14.sht` → **`texture/ksk_all_spaceterminal.dds`** (diffuse — THE swap target), `_n.dds` (normal), `_cn.dds`, shared `specular_lookup_35.dds` (don't touch)
- screen (animated 4-frame): `_screen_aef11(.base).sht` → `texture/ksk_all_spaceterminal_screen.01..04.dds`
- secondary mesh: `_sm_as9.sht` → `_sm.dds`, `_sm_emis.dds`

DDS formats: `ksk_all_spaceterminal.dds` = **256×256 DXT5, 9 mips, 87,536 bytes**; `_n.dds` = 256×256
uncompressed RGBA; `_screen.01.dds` = 128×128 DXT1; `_sm.dds` = 64×64 DXT5.

**Proven 2026-06-28:** dropping an edited `ksk_all_spaceterminal.dds` into
`D:\Code\swg-client-v2\stage\override\texture\` showed in-game (scribbled terminal). 04.2 must make
the toolkit do this (extract → stage edit → deploy-to-override-dir) with no manual copy.

## 3. Reproduce the trace (tooling)

The blender plugin's pure-Python TRE/IFF readers (no external exe) do all of this:
`swg_pipeline.tre_reader` → `parse_master_index(toc)` (reads `.toc`), `read_tre_entries(tre)`,
`read_tre_payload(tre, name)` (zlib-decompresses an entry); `swg_iff.dump.dump_tree(bytes)` (IFF tree).
Index all `*.tre` in the data root → resolve by lowercased logical path → dump/scan for asset refs.
(Session scratchpad held `trace_chain.py`/`probe.py`/`shaders.py` — ephemeral; re-derivable from the above.)
`sku0_client.toc` alone = 131 TREs / 193,475 indexed paths.
