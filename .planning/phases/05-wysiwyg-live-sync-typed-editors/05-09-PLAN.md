<interfaces>
UI-SPEC Surface 3 anatomy (018-A) — every element below is a must_have:
1. Dockview tab: `<file>.stf — Strings` + warn `●` mod-dot while dirty.
2. Crumb bar: `string/<locale>/<file>.stf · STF␠ · <N> entries (<M> shown)` (locale + magic bold,
   mono — the `STF␠` segment is a cosmetic display badge; it does NOT imply the on-disk magic is
   ASCII, per D-11 — the crumb copy stays as-is, only the underlying parser's magic check differs)
   · spacer · `⇄ Compare to base` · `＋ Stage` · `Save · run gate` (primary).
3. Toolbar: `Search keys and text…` input (filters by key AND localized text) · `＋ Add key` ·
   right count chip `<visible> / <total> keys[ · <K> modified]`.
4. The grid (flat table, virtualized): columns `key | crc32 | localized text (<locale>)`. `key`: mono,
   text color, nowrap, new rows get an inline key input. `crc32`: mono, faint, `--text-xs`,
   READ-ONLY/machine-owned, never editable; **new rows display `unset · assigned on first save`**
   (REVIEWS.md MEDIUM fix — corrected from the original "0x········ (auto on save)" phrasing, which a
   reader could mistake for "recomputed from this row's own text every save"; the actual behavior is:
   a NEW row has no sourceCrc yet, so the display is honestly "unset", and the value it gets assigned
   on first save is the client's own `nullCrc` convention (`0xFFFFFFFF`) for a default-locale entry —
   NEVER a hash computed from the row's own text). `localized text`: takes remaining width, wraps,
   double-click to edit, modified triple-encodes.
5. Gate bar: same shared chip machine as DTII with .stf copy — running: `gate: rebuilding index +
   payload…`; pass: `✓ byte-exact round-trip · CRC index rebuilt` + `→ staged in working changes` +
   modified marks clear. Right-aligned faint mono note — **CORRECTED per REVIEWS.md MEDIUM (the
   original "values are UTF-16LE · keys ASCII · CRC32 auto" was ambiguous): `values are UTF-16LE ·
   keys ASCII · sourceCrc preserved on save`** — this states the ACTUAL default-save behavior directly
   (D-10) rather than relying on a reader correctly disambiguating what "auto" meant; the engine's own
   on-disk field name (`sourceCrc`) is used instead of the generic "CRC32" to avoid implying a
   self-hash.
6. Fail state: inherits 014's anatomy via the shared GateBar/FailBanner — gate-fail chip + danger
   banner naming offset + expected/got bytes + not-staged guarantee.

D-10 (must be implemented — this is the behavior the corrected copy above describes accurately):
default save preserves every entry's `sourceCrc` byte-identical. A separate, explicit "↻ Mark
re-synced to source" action (new, not in the original sketch — CONTEXT-flagged addition) recomputes
`sourceCrc` from the DEFAULT-LOCALE file's current text via `addon.recomputeSourceCrcFromText` (05-05)
for the currently selected row(s) only, never as a blanket save-time side effect.
</interfaces>
