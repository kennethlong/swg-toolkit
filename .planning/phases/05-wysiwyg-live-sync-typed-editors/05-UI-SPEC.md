# Phase 05 — UI Design Contract (WYSIWYG Live-Sync & Typed Editors)

> Visual and interaction contract for LIVE-03 (viewport gizmo + live-sync HUD), DATA-01 (DTII grid
> editor), and DATA-02 (.stf strings editor). Generated by gsd-ui-researcher.
>
> **This phase FORMALIZES already-approved sketches — it is NOT a fresh design.** Sketches
> 011-B(+B2), 014-D, and 018-A were approved by the maintainer on 2026-07-07 and are the
> authoritative UI contract per AGENTS.md ("Sketches are the UI contract") and the gating todo
> `phase5-plans-must-match-sketches`. Every element enumerated in the Surface Contracts below MUST
> appear in plan `must_haves` — never a vague "render the editor". The token system is the
> **existing shipped** theme (`packages/renderer/src/themes/default.css`, cyan default); this
> contract reuses it verbatim and invents no new palette.
>
> **Refactor caveat (locked):** reusing or relocating an existing component (e.g. the
> `DatatablePanel` placeholder, `LiveInspectorPanel`, `Viewport.tsx`) does NOT excuse divergence
> from these sketches. Verification diffs each built surface against its sketch element-by-element.

## Spacing Scale

> **EXCEPTION — this project uses the shipped 3px DCC base grid, NOT the GSD-default 8-point
> scale** (established in 00/04.1 UI-SPECs; `default.css` is the single source of truth). Do not
> introduce 4/8/16px literals.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 3px | Glyph gaps, chip internal gap, axis-tag gap |
| `--space-2` | 6px | Compact element spacing, HUD card row padding, toolbar gaps |
| `--space-3` | 9px | Card body padding, rail section padding |
| `--space-4` | 12px | Panel/section padding, crumb-bar and gate-bar horizontal padding |
| `--space-6` | 18px | Larger group separation |
| `--space-8` | 24px | Major section breaks / empty states |

Fixed dimensions locked by the sketches (this phase):

- **Live-sync client card width = 224px** (011-B `.client-card`), top-right viewport overlay.
- **Gizmo-mode rail buttons = 40px wide**, vertical rail, left-edge, vertically centered (011-B `.mode-rail`).
- **Transform readout numboxes = 52px wide, right-aligned mono** (011-B `.vp-readout .numbox`).
- **Schema rail width = 250px**, collapsible (014-D `.rail`).
- **Grid row density**: compact DCC — cell padding `5px 10px` (DTII) / `6px 10px` (.stf), matching the sketches; grids MUST be virtualized at scale (VfsTree/HexInspector precedent — a real datatable/stf can have thousands of rows; DATA-01 requires a virtualized grid).
- Chrome: `--tabstrip-h: 30px` · `--statusbar-h: 22px` · `--titlebar-h: 30px` (locked, reuse).
- Radii: `--radius-sm: 3px` (chips, buttons, inputs, cells) · `--radius-md: 6px` (cards, HUD overlays).
- Editor tab width contract: DTII editor reads correctly at **~940–1080px**; .stf at **~880px**. Grids are **content-width / left-packed, never stretched edge-to-edge** (009's locked layout rule) — except the .stf `localized text` column, which takes remaining width (`width: 100%` in 018-A).

Exceptions: the 3px-grid deviation above (whole-project); the sketch-locked fixed dimensions listed.

## Typography

> Existing token scale. Weights: **400 (regular)** and **600 (semibold)**, plus a **700 micro-label
> exception** (10px type badges, 9px axis tags — sketch-locked in 014/011, maintainer-approved
> 2026-07-07). The 11/12/13/14px roles are 1px-apart because they are the shipped token scale — do
> NOT add a 5th text role in planning.

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Body / prose / banner text | 13px | 400 | 1.5 | `--text-base` |
| Chip / crumb / HUD row / count / hex / CRC / write-log | 11px | 400 (600 for chip & section labels) | 1.4–1.7 | `--text-xs` |
| Grid cells / row text / hex dump | 12px | 400 | 1.4 (1.7 hex) | `--text-sm` |
| Heading (panel title, modal title) | 14px | 600 | 1.2 | `--text-md` |

Conventions (from sketches, locked):
- Rail/section headers ("SCHEMA · COLS / TYPE", "WRITE LOG · THIS SESSION"): `--text-xs`, weight 600, `text-transform: uppercase`, `letter-spacing: .07–.08em`, mono, color `--color-text-faint`.
- Column type badges (`s`/`i`/`f`): `700 10px var(--font-mono)`, padded pill `1px 5px`, radius `--radius-sm`.
- Axis tags (X/Y/Z) in the readout bar: `700 9px var(--font-mono)`, 11px-wide colored square, dark text `#111`.
- All transform values, deltas, hex offsets/bytes, CRC values, pids, entry counts: `--font-mono`.

## Color

> 60/30/10 mapped onto the existing dark token system. Accent (cyan `#38bec9` default) is
> theme-switchable — reference vars, never hexes (exceptions listed below are sketch-locked
> fixed hexes that do NOT theme-switch).

| Role | Value (cyan default) | Token | Usage |
|------|----------------------|-------|-------|
| Dominant (60%) | `#181818` | `--color-bg` | App background, viewport backdrop, editor gaps |
| Secondary (30%) | `#242424` / `#2b2b2b` / `#323232` / `#3a3a3a` | `--color-surface`, `--color-surface-2`, `--color-header`, `--color-widget` | Panels, schema rail (`surface-2`), crumb/gate bars (`header`), inputs/buttons (`widget`), HUD overlays (translucent `rgba(16,20,20,.78–.9)` + `backdrop-filter: blur(4–5px)`) |
| Accent (10%) | `#38bec9` | `--color-accent` (+ `-hover`/`-text`/`-dim`/`-line`) | See reserved-for list |
| Destructive | `#e0584f` | `--color-danger` | Guard-blocked state, gate-fail state, revert affordances only |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The single **primary CTA per surface**: `Save · run gate` (`.abtn.primary`: `--color-accent-dim` bg + accent text; hover fills solid accent).
2. **Live state affirmation**: live-chip glyph `●` + card/readout border (`--color-accent-line`), `→ client ✓` write target, `read-verify ✓` guard row, `✓ saved` COW row, statusbar `ok` spans.
3. **Gate PASS**: `✓ byte-exact round-trip` chip (`gate-ok`: accent text + `--color-accent-dim` bg + `--color-accent-line` border) and the reverted-OK banner.
4. **Selected/active state**: active gizmo-mode button (`--color-accent-dim` fill + accent border), selected grid row (`--color-accent-dim`), active dockview tab underline, active segmented-toggle side, sort arrows, editing-cell input border (`--color-accent-line`), hex ASCII gutter.
5. Focus ring (`--focus-ring`) and active dockview sash.

**Secondary semantic colors (existing tokens — sparingly, always triple-encoded):**
- `--color-warn` `#e0a13a` — **the modified/dirty channel**: modified cell left-border/bg tint/`●` suffix, row `●`, tab `●`; offline live-chip glyph `○` + dashed border + `file-patch fallback` row; `→ staged (patch)` write target when offline; statusbar offline span.
- `--color-danger` `#e0584f` — guard-blocked card border + banner, gate-fail chip/banner, `Revert ALL` / `Revert to snapshot` buttons (danger-outline), per-write revert hover.
- `--color-info` `#4a8cff` — gate-running chip text, `→ staged in working changes` chip.

**Sketch-locked fixed hexes (do NOT theme-switch — they encode axis/type identity):**
- Gizmo axes: **X `#e0584f` / Y `#6db33f` / Z `#4a8cff`** — each axis ALWAYS carries its letter label (X/Y/Z text on the arrow and on the readout axis tag); color never carries axis identity alone.
- Column type badges: `s` `#7fb2ff` on `rgba(120,180,255,.13)` · `i` `#7dd68a` on `rgba(160,255,170,.10)` · `f` `#e8b46a` on `rgba(255,200,120,.12)` — the badge letter carries the type; color is reinforcement.
- Modified-cell tint `rgba(230,180,80,0.07)`; fail-banner tint `rgba(230,90,90,.08)`; hex highlight `rgba(230,180,80,.15)`.

**Live ↔ offline state encoding (011 locked rule — never color alone):**
| Channel | Live (injected) | Offline (file-patch fallback) |
|---------|-----------------|-------------------------------|
| Glyph | `●` (accent) | `○` (warn) |
| Border | solid `--color-accent-line` | **dashed** `--color-warn` |
| Label | `Live · injected` / `Live · pid <pid>` | `Offline` + `mode: file-patch fallback` row |
| Write target | `→ client ✓` (accent) | `→ staged (patch)` (warn) |

Offline is a **first-class safe mode, not an error state** (LIVE-05) — no danger styling, no error copy.

## Surface Contracts

### Surface 1 — Viewport gizmo + live-sync HUD (LIVE-03; sketch 011-B + B2, both approved)

The Phase-5 headline: drag a gizmo → the object moves in the running client. Every element below
is a plan `must_have`.

**HUD layout (all overlays absolutely positioned over the R3F canvas, z-ordered above it):**

1. **Shading/nav chips, top-left** — `Solid` / `Wire` / `Textured` (exclusive-select) + orbit `⟲` and frame `⛶` chips. Translucent chip style (`rgba(20,20,20,.7)` bg, `--color-border-soft` border, blur).
2. **Live-sync client card, top-right (224px)** — translucent, accent-line border (dashed warn when offline):
   - Header: **live chip** — `● Live · injected` (live) / `○ Offline` (offline), glyph + border + label per the state-encoding table.
   - Body rows (mono, `k` muted / `v` text): `client` (e.g. `SWG Infinity`), `pid`, `fps` (`—` offline), `last sync` (`0.2s ago` / `n/a` offline), `COW snapshot` (`✓ saved · <HH:MM:SS>` live / `○ staged` offline). Offline adds row `mode: file-patch fallback` (warn).
   - **Read-verify guard row (B2, permanent):** `read-verify` → `✓ client bytes = snapshot` (accent) or `✗ client bytes ≠ snapshot` (danger).
   - **Session write log (B2):** bordered-top section titled `WRITE LOG · THIS SESSION` (faint uppercase mono). Each row: relative time (`0.2s`, faint, 44px) + delta (`pos.x +0.42m`, `rot.y +12.5°`, `pos.z −1.06m` — `<channel> <signed value><unit>`, mono) + right-aligned `revert` button (ghost; hover turns danger). Every live write appends a row.
   - **`⟲ Revert ALL to snapshot`** button (danger-outline, full-width) below the log.
3. **Gizmo-mode rail, left edge, vertically centered** — vertical buttons 40px wide, icon over key label: `✥ W` Move · `⟳ E` Rotate · `⤢ R` Scale · `✛ Q` Universal. Active = `--color-accent-dim` fill + accent border + accent text. Keyboard shortcuts W/E/R/Q live.
4. **Transform gizmo on the model** — X/Y/Z arrows in the fixed axis hexes, each with a letter label and a wide invisible hit stroke (~16px); hover thickens line 2.6→4.2 and enlarges the label; center dot accent. Cursor `grab`/`grabbing`.
5. **Bottom transform readout bar, bottom-center** — translucent bar: `Pos` group (X/Y/Z axis tags + 52px right-aligned mono numboxes), `Rot` group, `Scale` group, then a border-left-separated **write-target indicator**: `⇄ writing to client → client ✓` (live) / `⇄ staging patch → staged (patch)` (offline). Numboxes mirror the gizmo live during drag AND accept typed values (numbox edit = same write path as a drag).
6. **Floating delta readout while dragging** — top-center, only during drag: `Δ pos.x +0.42m → client ✓` (axis accent-bold, value mono, target reflects live/offline).
7. **Corner axis gizmo, bottom-right** + **vp-stats, bottom-left**: `persp · <W>×<H> · <fps> fps · SAB ✓` (faint mono).
8. **Statusbar mirror (extend `StatusBar.tsx`)**: mesh name · `mode: Move (W)` · `sync: ● Live · injected · pid <pid>` (or `○ Offline — file-patch fallback`, warn) · `COW snapshot ✓` · `guard: read-verify ✓` (or `read-verify ✗ — write refused`, warn). Every surface (chip, card, readout, statusbar) switches together on live↔offline.

**B2 safety states (approved — part of the B contract, all three must ship):**

- **State: normal write.** Guard row green; each gizmo/numbox write appends to the write log; per-write `revert` undoes that write in the client; `Revert ALL to snapshot` restores the attach-time COW snapshot.
- **State: guard blocked (fails closed).** When the pre-write read-verify mismatches: card border turns danger; guard row `✗ client bytes ≠ snapshot`; danger banner: **`✗ Write refused.`** `The object's memory changed outside the toolkit (<addr>: expected <bytes>, read <bytes>) — the game or another tool moved it. Nothing was written.` Address + expected/got bytes are REAL values in mono. Actions: `↻ Re-read & retry` (ghost) + `⟲ Revert to snapshot` (danger-outline). **There is NO force-write affordance — its absence is contract.** Statusbar guard segment: `read-verify ✗ — write refused` (warn).
- **State: reverted.** Accent-toned OK banner: **`✓ Reverted.`** `Transform restored from the COW snapshot taken at attach (<HH:MM:SS>). The in-game object snapped back — nothing is staged.` COW row reads `✓ restored · just now`. Write-log rows go **struck-through at ~0.55 opacity with revert buttons removed** (history preserved, visibly dead). Readout bar + statusbar mirror the restored values.

**Interaction contract (LIVE-03 SC1):** the drag → SAB write → readout update path runs at 60fps
with **zero allocation** — HUD numbox/delta text updates during drag are imperative (refs/direct
DOM), never per-frame React state churn. Offline mode reroutes the identical gesture to the
staging path (`→ staged (patch)`), no feature gated behind injection (LIVE-05).

### Surface 2 — DTII datatable grid editor (DATA-01; sketch 014-D)

Full editor tab (main editor group, ~940–1080px). Anatomy top→bottom — every element is a plan `must_have`:

1. **Dockview tab**: `<file>.iff — Datatable` + warn `●` mod-dot while dirty (end of the triple-encoding chain).
2. **Crumb bar** (`--color-header` bg, mono): `FORM DTII ▸ FORM 0001 ▸ DATA` (tags bold/text-color) · **`Grid | Hex` segmented toggle** (active side accent-dim/accent) · spacer · action buttons: `⇄ Compare to base` (ghost) · `＋ Stage` (ghost) · **`Save · run gate`** (primary accent).
3. **Grid toolbar**: `Filter rows…` text input (filters by name column) · separator · `＋ Row` · `− Row` · right-aligned count chip `N rows · M cols[ · K cell(s) modified]` (faint mono).
4. **The grid** (Grid view; virtualized; content-width/left-packed per 009's rule):
   - Sticky header: column name + **type badge** `s`/`i`/`f` (fixed badge hexes) + accent sort arrow `▲`/`▼` on the sorted column; click header to sort (toggle direction).
   - Sticky left row-number column (`--color-header` bg, faint mono, right-aligned) — shows warn `●` before the number when any cell in the row is modified.
   - Cells: mono, muted (string column = full text color); hover `--color-widget`; `cursor: cell`; **double-click to edit** (inline input, accent-line border; Enter commits, Escape cancels, blur commits); typed coercion per column type (`i` → int, `f` → float).
   - **Modified cell triple-encoding**: inset 3px warn left border + `rgba(230,180,80,0.07)` bg + `" ●"` warn suffix → row-number `●` → tab `●`.
   - Row click selects (accent-dim row) and populates the rail's Selected-row inspector.
5. **Schema rail** (right, 250px, `--color-surface-2`, each section collapsible with rotating `▾` twisty):
   - `Schema · COLS / TYPE` — one row per column: type badge + name + storage type (`ascii·z` / `int32` / `float32`, faint).
   - `Selected row` — vertical key/value inspector of the selected row; modified values in warn; empty state `Click a row…` (faint).
   - `Round-trip gate` — kv rows: `last run` (`never` / `just now`), `result` (`—` / `✓ byte-exact` / `✗ mismatch @0x<off>`), `bytes` (`DATA <N> B`).
6. **Hex view** (toggle target): 3-column hex dump — faint offset gutter, bytes grouped 8+8, accent ASCII gutter — with the **edited cell's bytes highlighted** (warn tint) and caption: `highlighted: <col> (<type>) row <n> — the cell you edit in Grid view is these bytes`.
7. **Gate bar** (footer, `--color-header` bg) — the round-trip gate is a **first-class UI state machine**:
   | State | Chip | Behavior |
   |-------|------|----------|
   | not run | `round-trip gate: not run` (neutral) | default |
   | running | `round-trip gate: re-encoding DTII…` (info text, **dashed** border) | during re-encode |
   | pass | `✓ byte-exact round-trip (<N> B)` (gate-ok accent) | staged chip `→ staged in working changes` (info) appears; ALL modified marks clear (cell/row/tab) |
   | fail | `✗ round-trip mismatch — not staged` (gate-fail danger) | fail banner shows; **file is NOT staged — guaranteed** |
8. **Fail banner** (danger tint, above gate bar): `✗ Round-trip gate FAILED at DATA+0x<offset> — expected <bytes>, wrote <bytes>. Not staged.` Actions: **`Jump to bytes`** (switches to Hex view landed on the mismatching bytes) + **`Revert cell`**.

`Save · run gate` is NOT "save" — it is "re-encode and prove byte-exactness before anything is
staged" (CORE-05 standing gate surfaced as UI). Pass → staged; fail → diagnostic, never staged.

### Surface 3 — .stf strings editor (DATA-02; sketch 018-A)

Full editor tab, direct **sibling of 014** — same tabstrip/crumb/gate-chip anatomy (shared
components mandatory). One file = one locale; other locales are sibling files in the VFS tree (no
locale chips — 018-B was not selected). Every element is a plan `must_have`:

1. **Dockview tab**: `<file>.stf — Strings` + warn `●` mod-dot while dirty.
2. **Crumb bar**: `string/<locale>/<file>.stf · STF␠ · <N> entries (<M> shown)` (locale + magic bold, mono) · spacer · `⇄ Compare to base` · `＋ Stage` · **`Save · run gate`** (primary).
3. **Toolbar**: `Search keys and text…` input — **filters by key AND localized text** · **`＋ Add key`** · right count chip `<visible> / <total> keys[ · K modified]`.
4. **The grid** (flat table, virtualized): columns **`key | crc32 | localized text (<locale>)`**.
   - `key`: mono, text color, nowrap. New rows get an inline key input.
   - `crc32`: mono, faint, `--text-xs` — **read-only / machine-owned, never editable**; recomputed on save; new keys display `0x········ (auto on save)`.
   - `localized text`: takes remaining width; long strings wrap (`vertical-align: top`); **double-click to edit** (Enter commits, Escape cancels); modified value triple-encodes (warn left border + tint + `●` suffix) → tab `●`.
5. **Gate bar**: same shared chip machine as 014 with .stf copy — running: `gate: rebuilding index + payload…`; pass: **`✓ byte-exact round-trip · CRC index rebuilt`** + `→ staged in working changes` chip + modified marks clear. Right-aligned faint mono note: `values are UTF-16LE · keys ASCII · CRC32 auto`.
6. **Fail state**: inherits 014's anatomy — gate-fail chip `✗ round-trip mismatch — not staged` + danger banner naming offset + expected/got bytes + not-staged guarantee. (018-A doesn't demo it; the sibling contract requires it via the shared `GateBar`/`FailBanner`.)

Documented fallback (do not build now): if cross-locale pain shows in real use, 018-B's per-key
sibling-locale readout is the approved growth direction.

## Accessibility (Rule 1 — state never by color alone)

- **Live↔offline** = glyph (`●`/`○`) + border (solid/dashed) + label + color, on every surface simultaneously (chip, card, readout bar, statusbar).
- **Gizmo axes** carry letter labels (X/Y/Z) on arrows and readout tags — color is reinforcement, never the sole channel.
- **Modified state** triple-encodes: border + tint + `●` glyph, chained cell → row → tab.
- **Gate states** encode via glyph (`✓`/`✗`) + border style (solid/dashed) + full text label, not chip color alone.
- **Type badges** carry the letter (`s`/`i`/`f`); rail repeats the storage type in words.
- Global focus ring `--focus-ring` on all interactive elements (chips, mode buttons, numboxes, cells, rail headers); verify all three surfaces under `high-contrast` theme.
- Grid cells editable via keyboard (Enter to open edit on focused cell is acceptable extension; Esc always cancels). Segmented toggle and mode rail are radio-group semantics (`role="radiogroup"`/`aria-pressed`).
- Banners use `role="alert"` (guard-blocked, gate-fail) / `role="status"` (reverted, gate-pass).
