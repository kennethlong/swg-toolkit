<objective>
Refactor the TRE compression call sites (`TreArchive::extractEntry`'s `treInflate` call and `TreBuilder::build`'s `zlibCompress` call) behind a small pluggable `TreCodec` interface, per D-21's architecture constraint: "make the TRE read/write path a pluggable codec interface, not hardcoded, so custom compression/encryption can be dropped in" (open-source extensibility for forks like Restoration's proprietary v6000 encryption).

This is a SEAM refactor, not new functionality: `TreArchive`/`TreBuilder` callers stay the same; only the compression call becomes indirect through a codec registry. The existing V6000-write-refusal behavior (`TreBuilder.cpp:204` `isEnumerateOnly` throw) and the existing per-payload read-side graceful classify (MOUNT-05, already landed in 04.3-10/11) are BOTH preserved — this plan does not add v6000 write support, it makes the SEAM pluggable for a future/fork codec to do so.

Purpose: architecture constraint from the product-thesis todo (D-21) — the codec interface, not new compression capability.
Output: `TreCodec.h`/`.cpp` + `TreArchive.cpp`/`TreBuilder.cpp` wired through it, zero behavior change for existing fixtures.
</objective>
