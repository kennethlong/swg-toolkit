## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `vite.main.config.ts` produced a non-functional bundle when run standalone (3 compounding root causes)**
- **Found during:** Task 1 (CI build-before-E2E fix) — verifying the acceptance criterion "running the same three commands locally produces `.vite/build/main.js`"
- **Issue:** The plan's action text assumed a bare `vite build -c vite.main.config.ts` would "just work" the way it does under `electron-forge package`/`start`. It does not — forge's `VitePlugin` injects several things at build time that a standalone invocation never gets:
  1. **Wrong output path/format:** no `outDir`/`build.lib` → output landed at `dist/assets/main-<hash>.js` as an ES module, not `.vite/build/main.js` as CJS (what `package.json#main` and the E2E harness require).
  2. **Unresolved globals → crash:** `main.ts` references `MAIN_WINDOW_VITE_DEV_SERVER_URL`/`MAIN_WINDOW_VITE_NAME`, normally forge-injected `define`s. Left unresolved, they threw a `ReferenceError` inside `app.whenReady().then(...)`, crashing before any window was created — this is what made `electronApplication.firstWindow()` time out in `e2e/01-boot.spec.ts`.
  3. **Node builtins stubbed to `{}`:** without every builtin module name (bare + `node:`-prefixed) in `rollupOptions.external`, Vite's browser-externalization fallback replaced `import path from 'node:path'` (and `node:fs`) with empty object stubs — `resolve.conditions: ['node']` alone does NOT prevent this. Runtime symptom: `TypeError: s.join is not a function`.
- **Fix:** Added explicit `outDir`/`emptyOutDir`/`output.format+entryFileNames` to `build`; added explicit `define` for the two forge globals (matching the production/packaged path: no dev server, `app://` protocol); added a `NODE_BUILTINS` constant (`node:module`'s `builtinModules`, bare + `node:`-prefixed) to `rollupOptions.external`; kept `resolve.conditions`/`mainFields` as a complementary (but insufficient alone) signal.
- **Files modified:** `vite.main.config.ts`
- **Verification:** Direct `electron.exe .` launch produced a clean boot (only benign GPU/network-service noise, no `TypeError`/`ReferenceError`); `e2e/01-boot.spec.ts` 8/8 pass (including the SC-2 native-addon smoke test cited in Task 1's acceptance criteria); full lean-job spec set (01-04) run locally — 19/22 pass, 2 pre-existing unrelated failures (see Deferred Items below), 1 pre-existing `test.fixme`.
- **Committed in:** `0b9cbc1` (Task 1 commit)

**2. [Rule 3 - Blocking] `vite.preload.config.ts` silently wiped the shared `.vite/build/` output dir**
- **Found during:** Task 1, same verification pass — `.vite/build/main.js` existed after the main build but vanished after the preload build ran.
- **Issue:** Forge's own `VitePlugin` always forces `emptyOutDir: false` on every build config it drives, specifically "to prevent multiple builds from interfering with each other" (its own comment). `vite.preload.config.ts` never set this itself (relying on forge to inject it), so Vite's default `emptyOutDir: true` deleted `.vite/build/main.js` before writing `preload.js`.
- **Fix:** Added `emptyOutDir: false` directly to `vite.preload.config.ts`'s `build` config.
- **Files modified:** `vite.preload.config.ts`
- **Verification:** Re-ran the 3-command build sequence in CI order; `ls .vite/build/main.js .vite/build/preload.js .vite/renderer/main_window/index.html` — all three coexist on disk.
- **Committed in:** `0b9cbc1` (Task 1 commit)
