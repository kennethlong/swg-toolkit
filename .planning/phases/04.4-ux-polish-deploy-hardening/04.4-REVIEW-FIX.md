## Fixed Issues

### CR-01: TRE name-block `fileNameOffset` never bounds-checked — OOB read on hostile archives

**Files modified:** `packages/native-core/modules/core/tre/TreArchive.cpp`
**Commit:** 2a6bb01
**Applied fix:** Validate `fileNameOffset` once at parse time in the TOC unpack loop —
`< 0 || >= nameData.size()` throws `T-01-02` — so `resolve()`, `resolveTombstoneIndex()`,
`nameAt()` (and `TreBuilder::repack` via `nameAt`) can index `m_nameBlock` safely.
Strict `<` also guarantees NUL termination via `std::string::c_str()`'s terminal NUL.
Matches the file's existing T-01-* hardening comment style.

### WR-01: Effect.cpp read SCAP big-endian; client reads little-endian

**Files modified:** `packages/native-core/modules/core/formats/Effect.cpp`, `packages/native-core/modules/core/formats/Effect.h`
**Commit:** 783ee06 — **fixed: requires human verification** (no existing test inspects
`scapValues`; the CI synthetic fixture is single-IMPL, per the review itself. Recommend adding a
multi-IMPL fixture assertion.)
**Applied fix:** SCAP now read via `readU32LE()` cast to int32 (ground truth cited in-code:
`../swg-client-v2` ShaderImplementation.cpp:375,435,494 `read_int32` raw memcpy + Iff.h:575-580 —
same convention as PTXM textureTag; NOT re-derived from docs/). Deleted the now-unused
`readI32BE()` helper entirely (zero remaining references) and updated Effect.h's STRUCTURE +
IMPL SELECTION RULE notes to state SCAP is raw-LE and must not be byte-swapped (swap is not
order-preserving → would invert highest-max-SCAP selection).
