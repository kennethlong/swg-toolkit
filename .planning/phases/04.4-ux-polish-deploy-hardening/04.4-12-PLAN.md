<objective>
Wire the two server-push services (04.4-07 Core3, 04.4-08 swg-main) into a real UI entry point: a "Server Push" section in the existing `VcsPanel.tsx` (deploy-adjacent, already the panel that surfaces Git/LFS actions), visible only when the open workspace's `serverConfig` (captured by the existing 007 wizard step 3, `WorkspaceInfo.serverConfig`) is set. This is the LAST step of the interface-first ordering for the product-thesis server-push work: contracts existed already (Phase 4.1, capture-only) → services built (07/08) → wire here.

**Round-2 scope note:** the real-running-server checkpoint (D-22's "working deploy target" bar) that round-1 placed as this plan's Task 3 is now its OWN plan, **04.4-15** (Wave 3), so this plan stays fully autonomous and does not stall the Wave 2→3 barrier for 04.4-14 (see revision note above). This plan delivers the automated UI wiring only; 04.4-15 delivers the maintainer-confirmed real-server round-trip on top of it.

**PATH CONTRACTS (locked, identical to 04.4-07/08):**
- Core3: `confDir = path.join(serverConfig.path, 'conf')` (`serverConfig.path` = the `MMOCoreORB/bin` root).
- swg-main: `servercommonCfgPath = path.join(serverConfig.path, 'exe', 'shared', 'servercommon.cfg')` (`serverConfig.path` = the swg-main repo root; VERIFIED 2026-07-03 this relative path exists).

**RESET-RECORD-CLEAR CONTRACT (round-2, locked — no hedge):** `resetCore3TreOverride`/`resetSwgMainOverride` NEVER clear their persisted record files themselves (04.4-07/08's firm, round-2-locked contract). This plan's Reset handler is the SOLE caller that clears them: it ALWAYS calls `clearCore3PushRecordFile`/`clearSwgMainPushRecordFile(studioDir)` explicitly, immediately after a successful `resetCore3TreOverride`/`resetSwgMainOverride` call — never conditionally, never "if the service doesn't already do it."

**Known, accepted, PRE-EXISTING limitation (round-2, assessed not fixed — see revision note above):** `projectSlug` (passed to `pushCore3TreOverride`) is derived from the workspace's DISPLAY NAME, not a stable per-project id — two projects sharing a display name could collide. This is the SAME basename-only collision surface `getStudioDir` already has since Phase 4.1 (not a new regression), and a real fix needs a stable UUID added to `WorkspaceBindingMeta` — out of scope for this plan.

Purpose: without this plan, `pushCore3TreOverride`/`pushSwgMainOverride` are only reachable from tests — this closes the vertical slice UI → service → disk (the real-server leg is 04.4-15).
Output: a small "Server Push" section in `VcsPanel.tsx` with Push/Reset buttons, disk-backed record rehydration, and success/error feedback.
</objective>
