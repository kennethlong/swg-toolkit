## Decisions Made

- STAG's version tag is a direct leaf CHUNK inside FORM STAG (confirmed by reading `ShaderImplementationPassStage::load` — `iff.enterChunk(TAG_0000)`), not a FORM wrapping a DATA chunk like PTXM's version children. `parseStag` uses `findChunk()`, mirroring `parsePassData`'s pattern rather than `parsePtxm`'s FORM-loop pattern.
- Fixed-function stage index = 0-based sibling position among `FORM STAG` children (no separate index field exists at the wire level for fixed-function stages, unlike PTXM's explicit `textureIndex`).
- `extract-effect-fixtures.cjs` reads bytes directly via `readMountEntry(handle, archiveIndex, entryIndex)` off `searchMount` hits rather than `resolveEntry(handle, path)` — `searchMount` hits carry only `{entryIndex, archiveIndex}`, no `.path` field (by design, per T-01-06: never ship the full name list in bulk search results). The `extract-ans-fixtures.cjs` pattern cited in the plan's interfaces block (`resolveEntry(handle, entry.path)`) does not actually work as written against the current native binding contract; this script instead lets `parseEffect`/`parseShader`'s own FORM-tag check filter non-matching hits via try/catch.
- The companion body-droid `.sht` (Bug-1 regression fixture referenced in a pre-existing `describe` block) was NOT found on this client install (`body_droid_m_01_r_3`, `body_droid`, `droid_m_01`, `a_body_droid` all returned 0 search hits) — the script warns non-fatally rather than failing, since that fixture/test is out of this plan's acceptance-criteria scope (the plan only requires the EFT fixture + EFCT describe-block tests to activate).

- **Found during:** Task 2 (writing `extract-effect-fixtures.cjs`)
- **Issue:** The plan's interfaces section cited `extract-ans-fixtures.cjs`'s `resolveEntry(handle, entry.path)` as "the exact script pattern to mirror." Running the first draft against the real client install threw `TypeError: Cannot read properties of undefined (reading 'toLowerCase')` — `nativeCore.searchMount()`'s native binding (`tre_binding.cpp:335-370`) returns `{entryIndex, archiveIndex}` only, never `.path` (by design, T-01-06 disposition: never ship bulk file-name lists). `entry.path` was always `undefined`.
- **Fix:** Rewrote the extraction loop to call `readMountEntry(handle, hit.archiveIndex, hit.entryIndex)` directly — no path needed. Used `parseIff` + `parseEffect`/`parseShader`'s own format-tag validation (wrapped in try/catch) to filter non-matching hits, since there's no path-based extension filter available.
