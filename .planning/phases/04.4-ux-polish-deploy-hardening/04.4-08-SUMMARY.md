## Decisions Made

- Reused `deployLoose`/`resetLoose` directly (imported, not reimplemented) — the B3
  snapshot-before-overwrite and path-safety guard logic is identical to the client-side loose
  model; `swgMainServerPush.ts` only supplies the swg-main-specific `resolveSwgMainOverrideDir`
  and the cross-restart JSON persistence wrapper.
- `resolveSwgMainOverrideDir` performs its own liveness pre-check (throws the named error) rather
  than leaving that to the caller — mirrors `core3ServerPush.pushCore3TreOverride`'s pattern of
  surfacing a clear error before any parse/write work begins.
- Did NOT reuse `clientLocator.scanSharedFile` for parsing `servercommon.cfg` — its key shape
  (`searchTree_<sku>_<N>=`, slot-number-only) differs enough from the server's
  (`searchPath<N>=`, value-per-line, no sku infix) that a small dedicated regex parser was
  warranted per the plan's "prefer reuse... or a small dedicated parser" guidance.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected the same-tier `searchPathN` tie-break direction (plan/RESEARCH.md claimed the wrong winner)**
- **Found during:** Task 1 (source-trace confirmation step)
- **Issue:** `04.4-08-PLAN.md` (and the `04.4-RESEARCH.md` ADDENDUM it cites) asserted that a
  same-priority-tier tie in `[SharedFile] searchPath<N>=` resolves to the **earlier-declared**
  value winning, stating this as a "correction" of a prior "later-added wins" assumption, and
  specified the test should assert the fixture's first-declared `searchPath2` value wins
  (`sys.shared/compiled/game/`). Re-deriving the actual `std::lower_bound` + `vector::insert`
  semantics on the cited `TreeFile.cpp:285-308`/`:294-296` code (not just the comment at
  `:294-296`, which is misleading) shows the OPPOSITE: for an exact-priority tie, the
  newly-inserted node lands BEFORE existing same-priority nodes in `ms_searchNodes`, and since
  `TreeFile::open` walks front-to-back, the **most-recently-added (last-declared) node wins**.
  This is corroborated by an EXISTING, currently-passing, project-internal test for the
  byte-identical shared `addSearchNode` mechanism on the client side
  (`packages/harness/test/tre-override.test.ts` "tre priority tie-break" suite,
  `packages/native-core/modules/core/tre/TreMount.h:13-20`, and the locked decision in
  `.planning/STATE.md` "[Phase 01, Plan 02]: Same-priority tie-break: SECOND-mounted
  equal-priority archive wins"). Implementing the plan's stated (incorrect) rule would have
  shipped a resolver that writes into the WRONG directory against a real swg-main server whenever
  a priority tier declares more than one value — the exact kind of "ground truth vs. AI-generated
  research doc" divergence this project's de-anchoring protocol exists to catch.
- **Fix:** Implemented and tested the corrected rule — `resolveSwgMainOverrideDir` picks the
  LAST-declared value within the highest-numbered tier. `swgMainServerPush.test.ts`'s test (a)
  asserts the winner is `sys.server/compiled/game/` (the SECOND line in the fixture cfg), not
  `sys.shared/compiled/game/` (the plan's stated expectation). The source-trace citation comment
  at the top of both the test file and the implementation module documents the full
  re-derivation and cites the falsifying precedent. `docs/05-server-integration/swg-main-parity.md`
  states the corrected conclusion as the canonical ground truth for this mechanism, explicitly
  marking the `04.4-RESEARCH.md` ADDENDUM's claim superseded for this one point.
- **Files modified:** `packages/renderer/src/services/swgMainServerPush.test.ts`,
  `packages/renderer/src/services/swgMainServerPush.ts`,
  `docs/05-server-integration/swg-main-parity.md`
- **Verification:** `swgMainServerPush.test.ts` test (a) is GREEN against the exact fixture cfg
  text from the plan's `<interfaces>` block; the resolved directory is
  `sys.server/compiled/game/`.
- **Committed in:** `8111507` (Task 1 RED — test pins the corrected assertion), `c5998cb`
  (Task 2 GREEN — implementation + doc)
