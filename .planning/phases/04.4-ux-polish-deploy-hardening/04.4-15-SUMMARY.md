# Phase 04.4 Plan 15: Real-Server Push→Reset Round-Trip (D-22) Summary

**The maintainer confirmed the full push→reset loop against a REAL running Core3 (WSL2) instance — and the checkpoint did exactly what it exists for: the first push attempt failed against the live server (EPERM into a nonexistent /home/swgemu path) because the TrePath resolver only understood the dotted config-local form, a defect every synthetic fixture missed. ## Checkpoint record (task 1, checkpoint:human-verify, blocking)

- **Flavor tested:** core3-wsl2 — live Core3 on WSL2 Debian, conf at `\\wsl.localhost\Debian\home\kenny\workspace\Core3\MMOCoreORB\bin\conf`, TrePath `/mnt/d/SWGEmu-Client/SWGEmu` (→ `D:\SWGEmu-Client\SWGEmu`, 53 real .tre files present).
- **Maintainer resume signal (verbatim):** "approved" (2026-07-06), after the fixed push succeeded and the round-trip was exercised per the plan's how-to-verify.
- **Real-server defect found and fixed in-task (T-04.4-21b materialized):** the live `config-local.lua` assigns `TrePath` as a bare Lua **global** (legacy style: `TrePath = "/mnt/d/SWGEmu-Client/SWGEmu"` with aligned padding and a trailing comment) — NOT the dotted `Core3.TrePath` form. Ground truth re-read of `../Core3` `ConfigManager.cpp:57-75`: after parsing the `Core3` table, a second pass parses the Lua global table with prefix `Core3`, so the bare global OVERRIDES the table value on a real server. Our resolver accepted only the dotted form in config-local and silently fell back to `config.lua`'s stock `/home/swgemu/Desktop/SWGEmu` default → `EPERM: mkdir '\\wsl.localhost\Debian\home\swgemu\Desktop\SWGEmu'`. The failure occurred BEFORE any server-side write (no config-local mutation, no record persisted) — the push's write-ordering held up.
- **Fix:** `resolveLinuxTrePath` now tries dotted-then-bare in config-local.lua; new test `(b2)` replicates the real live file shape byte-for-byte (padding, trailing comments). The prior fixture had labeled the dotted-only shape "maintainer real shape" — corrected. Suite 14/14 green.
