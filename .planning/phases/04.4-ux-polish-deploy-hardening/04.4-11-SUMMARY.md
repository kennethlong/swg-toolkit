# Phase 04.4 Plan 11: Main-Process Log Forwarding + Deploy/Reconcile/Mount Instrumentation Summary

**Main-process dialog events now reach the renderer's Log tab via a `main-log` IPC push folded into the existing `installConsoleCapture()` call site, plus structured Log-tab entries at mount/seal/reconcile/deploy/reset call sites — closing D-12/D-13's "capture scope = renderer + main" and D-14's day-one usefulness requirement.**

## Performance

- **Duration:** ~15 min
- **Tasks:** 2
- **Files modified:** 7

## Accomplishments
- `MainLogEvent` one-way IPC type added to `contracts/src/ipc.ts`; `main.ts` forwards `'app ready'` plus invoke/cancel events from the 3 dialog `ipcMain.handle` blocks via a `sendMainLog()` helper
- The main-log-forward subscription was folded INTO `logService.ts`'s existing `installConsoleCapture()` function body (at the exact insertion-point comment 04.4-02 left) rather than a new function/call site — verified `ConsolePanel.tsx` is untouched (still exactly 1 module-scope call)
- The one-time "app ready" log line moved to `win.webContents.once('did-finish-load', ...)` to avoid the "renderer isn't listening yet" race
- 4 renderer service files instrumented with `log()` calls at mount-complete/mount-error, version-seal-complete, reconcile-noop/reconcile-apply, and deploy-success/deploy-error/reset-success/reset-error points — all side-effect-only, verified against each file's existing test suite

## Deviations from Plan

None — plan executed exactly as written, including both round-2 fixes (VITEST guard placement inside `installConsoleCapture()`, and `did-finish-load` timing for the "app ready" line).

One minor addition beyond the plan's literal text: the `packPatch` build-failure catch inside `handleDeploy` (a third error branch alongside the two the plan named) also received a `log('error', ...)` call, for consistency with "every handleDeploy error branch gets a caught-message log entry" — a side-effect-only addition, verified against existing DeployDialog behavior/tests.

## Issues Encountered

Two type-only fixes were needed to land the plan's specified code cleanly (not behavior changes, both fixed while implementing Task 1/2, no separate deviation write-up needed since they were purely mechanical type-shape corrections to make the plan's own action text compile):
- `packages/contracts` needed a `pnpm --filter @swg/contracts run build` to regenerate `dist/` before `packages/backend`'s `tsc --noEmit` could see the new `MainLogEvent` export (contracts resolves via `dist`, which is gitignored — no commit needed for that rebuild).
- The `ipcRenderer.on` listener callback's parameter type was tightened to `unknown` + an in-body cast, since the ambient `(...args: unknown[]) => void` listener type doesn't structurally accept a `MainLogEvent`-typed second parameter.
- `syncLiveToVersion.ts`'s final-return file-count log uses `LooseDeployRecord.writtenFiles.length` (not a nonexistent `entries` field) when the record is loose, falling back to the flattened target's entry count otherwise.
