# Phase 04.4 Plan 02: Console/Log Tabs Live Wiring Summary

**Ring-buffer `logStore` (2000-entry FIFO cap) + `logService` console-capture API wired to the already-registered Console/Log dockview panels, with capture installed at module scope so it runs from true app boot rather than first-tab-open.**

## Accomplishments

- Implemented `logStore.ts`: Zustand store with `entries: LogEntry[]`, `append()` (FIFO-capped at
  2000 via `.slice(-2000)`, mitigating T-04.4-05 unbounded-growth DoS), and `clear()`.
- Implemented `logService.ts`: `installConsoleCapture()` wraps `console.log/warn/error` (mirrors
  into `logStore` as `channel:'console'` while still invoking the original method) and installs
  `window` `'error'`/`'unhandledrejection'` listeners producing `channel:'console', level:'error'`
  entries. Idempotent via an `installed` guard. `log(level, channel, message)` is the direct
  structured-event API. `resetConsoleCaptureForTests()` (round-2 addition) genuinely unwraps
  `console.*`, removes the window listeners, and clears the guard for cross-test-file isolation.
- Rewired `ConsolePanel.tsx` to subscribe to `logStore` (filtered `channel==='console'`), render
  level-colored rows (info/warn/error), autoscroll-with-pause-on-scroll-up, a Clear button, and
  click-row-to-copy. `installConsoleCapture()` is called at MODULE SCOPE (top of file, outside the
  component function), guarded by `process.env.VITEST` so unit tests importing the file don't wrap
  console during a test run.
- Rewired `LogPanel.tsx` identically but filtered to `channel==='log'`, without its own capture
  install (single shared store — Clear from either panel empties both).
